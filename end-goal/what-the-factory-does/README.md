# What the factory does

A **fully autonomous software factory and operations**: it refines intent, produces the software, deploys it, monitors it, finds issues, and fixes bugs, on its own. It also runs itself: it decomposes [intent](../how-the-factory-works/02-intent-into-items/01-intake/README.md) into [items](../how-the-factory-works/01-one-pipeline.md), dispatches its own [agents](../how-the-factory-works/01-one-pipeline.md) onto them, [gates](../how-the-factory-works/03-gates/01-where-a-gate-is-and-what-decides-it.md) its own output against a [score](../how-the-factory-works/04-risk-score/README.md) it learns, revises [what those agents are told](../how-the-factory-works/10-fleet/03-what-an-agent-is-told/README.md) from what its own decisions record, and escalates what it cannot finish. It does not compose its own [fleet](../how-the-factory-works/10-fleet/README.md): what an agent is told is the factory's, what it runs on is a human's — the sharpest division in the document.

The factory is a product — each customer runs an isolated, self-hosted install. There is no tenancy: no shared install, no multi-tenant model, nothing about one customer's data another's factory could reach. The absence is a decision, not a gap left to fill. What it buys is that the [one graph](01-tight-integration.md) of records, every record, every [end-user report](../how-the-factory-works/02-intent-into-items/01-intake/02-reports.md), every line an agent read, is one customer's, reachable by no other customer and by nobody hosting a shared install, which is the condition a regulated customer installs under at all. The [provider](../how-the-factory-works/10-fleet/01-what-an-agent-runs-on.md) an agent reaches its model through is a named party in that claim: what an agent is handed, the repository, the reports and what a run printed, crosses to a named credential's provider at every agent call, and the [grouper](../how-the-factory-works/02-intent-into-items/01-intake/02-reports.md)'s read of every arriving report is such a call. What it costs is that nothing learned in one install reaches another: the [per-author prior](../how-the-factory-works/04-risk-score/01-factors-at-least.md) an install narrows over months is that install's alone, and a provider retiring a model version destroys it in every install at once with nothing to amortize it across them. The one channel is the product itself: the [role prompts](../how-the-factory-works/10-fleet/03-what-an-agent-is-told/README.md), [evaluation sets, and starting priors](../how-the-factory-works/10-fleet/02-a-model-under-a-name.md) it ships carry what [the builder](05-what-the-customer-runs-it-under.md) measured on the builder's own work, never what a customer's factory learned.

Below the install there is no boundary, and that is decided too. A [project](../how-the-factory-works/11-screens/01-work-ops-factory-people.md) is a grouping of work: the [factory-wide settings record](../how-the-factory-works/09-gate-policy/02-one-shape-across-all-of-them.md) is one record, a [halt](../how-the-factory-works/09-gate-policy/04-stopping-the-factory.md) stops every service, every [People](../how-the-factory-works/11-screens/01-work-ops-factory-people.md) row reads all four screens, and one fleet and one set of priors serve every project. A customer with two regulatory regimes, or two business units that may not read each other's records, runs two installs, one per boundary they need, and the boundary between them is the one this section already sells. Two installs are two graphs, two logs, two report stores, and two sets of credentials the resolver of seam 3 of [_Deferred, but not designed out_](../deferred.md) answers for. What a second install duplicates is the fleet, the priors and their calibration, gate policy, and the [People declaration](../how-the-factory-works/11-screens/01-work-ops-factory-people.md), each learned or authored again from nothing; what it never duplicates is a record. A boundary inside an install is refused. It would need a second scope on nearly every mechanism [_Gate policy_](../how-the-factory-works/09-gate-policy/README.md) gathers: a halt scoped to a project, a People row scoped to a project, a resolver refusing a credential across projects. Two installs give that separation at the cost of a second fleet. What the refusal costs is that the choice is made at install and cannot be revisited: an install is one chained [log](../deferred.md), so two installs are never merged and one is never split, and a customer who drew the line wrong runs the second install from nothing.
