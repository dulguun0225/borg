# Glossary

A line here is for a word the wider software industry already owns that this document uses in a narrower or different sense, so a reader arriving with the industry meaning is not left confidently wrong. [`rollback`](how-humans-do-it/06-releases/06-rollback.md) is the line that matters most, because an SRE reader assumes a capability this design withholds and would otherwise rely on it. This is not an index of the document's vocabulary, and a line here does not admit a term — a term is introduced where it is first used, in the prose of the file using it. Nor is it a second place a decision is written: the line says what the term names, the section says what follows from it, and where the two could differ the section is right. That keeps it clear of `CLAUDE.md`'s rule against a list of answers kept outside the sections that own them — a resolved question is folded into its section and never restated here.

Which words have a line here is decided in the commit that adds or removes one — this file is
the only copy of that list.

Read it when a sentence uses a name you cannot place. Nothing depends on reading it first.

- **artifact** — what a stage authors about one item and a gate decides over: the spec, the implementation plan, the tasks, and the implementation, with the criterion encoding authored beside that last one and decided at the same gate. [One pipeline](how-humans-do-it/01-one-pipeline.md)
- **candidate** — an item plus its build: identity enough to deploy, test, and reject, from build until merge to master. It is not a record. [What a build is called, and when](how-humans-do-it/06-releases/03-what-a-build-is-called-and-when.md)
- **decision** — what a gate firing writes into the append-only log: an open event carrying the factor vector, and a close event naming it and carrying the verdict. [Where a gate is, and what decides it](how-humans-do-it/03-gates/01-where-a-gate-is-and-what-decides-it.md)
- **detector** — anything of the factory's own that raises an intent: [the health monitor](how-humans-do-it/08-operations.md#the-health-monitor) still running after its window closed, a consumer breaking in its own error rate, a permanent constraint no intent names, an advisory naming a package a shipped build resolved. It raises one per condition, not per observation; later evidence attaches to the intent already raised. [Intake](how-humans-do-it/02-intent-into-items/01-intake/README.md)
- **Edit in place** — the gate action where a human edits the artifact under decision instead of rejecting the item to get a different one. Offered at Decomposition and at every artifact gate but Implementation. [Actions at each gate](how-humans-do-it/03-gates/03-actions-at-each-gate.md)
- **the graph** — the one linked set of records the product is built around: intent, item, spec, build, gate decision, deploy, incident, and score, joined by links rather than matched across systems. [Tight integration](what-the-factory-does.md#tight-integration)
- **hold** — a stop that leaves the event queued with the change still good, offered at the deploy rows alone. Three kinds, and only a human's is written as a decision. [What a gate may change](how-humans-do-it/03-gates/04-what-a-gate-may-change.md)
- **incident** — a record on a production environment, written by the health monitor against the release running there, never by a human. [Incidents](how-humans-do-it/08-operations.md#incidents)
- **intent** — what arrives and what everything links back to: one record from three sources — an owner's request, a group of end-user reports, or something the factory found. [Intake](how-humans-do-it/02-intent-into-items/01-intake/README.md)
- **item** — the unit the factory moves: one thing that can ship by itself, one timeline, one release. [One pipeline](how-humans-do-it/01-one-pipeline.md)
- **page** — the narrow channel, for a wait where the deployed software is worse until a human ends it. The only channel that widens and the only one that writes a record. [Pages](how-humans-do-it/08-operations.md#pages)
- **the pipeline** — the one path every item takes: the stages that author it and the gate at each boundary. There is no second path and no bypass. [One pipeline](how-humans-do-it/01-one-pipeline.md)
- **release** — the name a build has on master, from merge onward, and the record where the graph joins. [The release record](how-humans-do-it/06-releases/02-the-release-record.md)
- **rollback** — a deploy event that shifts traffic onto the instances of the release it returns to, still running, minting and retiring no number. [Rollback](how-humans-do-it/06-releases/06-rollback.md)
- **seam** — a boundary declared between two writers, or between the factory and something not designed yet, so that neither side reaches past it. [_Deferred, but not designed out_](deferred.md) names five of the second kind — the actor, the log, the credential resolver, reaching a platform, and the principal on a call — and numbers them. [Deferred, but not designed out](deferred.md)
- **service** — one repository with one long-lived branch, and no repository holds two. Master, the release number, and the queue's ordering are all per service. [Decomposition](how-humans-do-it/02-intent-into-items/03-decomposition/README.md)
- **store** — a contract whose consumer is the service's own past, which is why it promises forward as well as backward. The bare word takes this sense; the artifact store and the report store are components, named in full wherever they appear, and neither is this line. [The store is a contract too](how-humans-do-it/07-contracts.md#the-store-is-a-contract-too)
