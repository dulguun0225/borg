# Factors, at least

Four groups of factor, named so a human can argue with them, and the set is open.

- **The change** — size, how much of the system it can affect, churn in the item's [area](../02-intent-into-items/03-decomposition/02-what-an-item-names.md), reversibility. Test coverage is deliberately not among them: it would be computed from the [encodings](../03-gates/07-what-particular-gates-decide/05-implementation.md) the scored agent authored in the same [stage](../01-one-pipeline.md) as the code, so the scored author would set the factor — assertions piled on accessors beside an untested payment path read as high coverage — and it would lower the number exactly when it was gamed, with the [analysis window](../08-operations/02-the-analysis-window.md) then closing `cleared` — its no-failure exit — on a quiet service, and the manoeuvre narrowing the prior of the author that performed it. It returns if something ever derives it independently of the author, the same condition [_Implementation_](../03-gates/07-what-particular-gates-decide/05-implementation.md) states for making the encoding itself mechanical. Leaving it out costs this: the change group reads a tested change and an untested one alike; what carries that information instead is [the run](../05-environments/04-what-the-candidate-environment-decides.md) — a [criterion](../03-gates/07-what-particular-gates-decide/02-spec.md) in force with no encoding naming it is already a rejection at [_Implementation_](../03-gates/07-what-particular-gates-decide/05-implementation.md).
- **The author** — the **per-author prior**, one per human and per AI model version, computed from that author's own work with the changes a human [undid after they shipped](../../what-humans-do.md) (10) and the [rollbacks](../06-releases/06-rollback.md) marked. A [revert's deploy](../08-operations/03-overlapping-windows.md) delivers several releases under one window, and that window's close moves no prior in either direction: one comparison over several changes is a label the evidence does not support, toward fault and toward trust alike. Only the release the [search](../08-operations/03-overlapping-windows.md) names takes a failed batch's outcome, and where no search runs or it names nobody, the batch teaches nothing — the reading an absent input already gets. A deploy has no author: the [deployer](../08-operations/01-the-health-monitor.md), the component that performs every deploy, is not one, so a deploy accrues no [attempt](../03-gates/05-the-attempt-limit.md) and moves no prior, and the outcome that does move one — the [window](../08-operations/02-the-analysis-window.md) closing on the release — is read against the artifact's author and never against what deployed it. A prior read as a list of only the bad outcomes could never narrow toward trust: what narrows it is the work nobody undid, so every outcome on that author's [artifact](../01-one-pipeline.md) moves it, a [window](../08-operations/02-the-analysis-window.md) closing without failing the release included — except a window whose comparison received no volume at all, evidence about nothing and narrowing nothing, the reading [_The analysis window_](../08-operations/02-the-analysis-window.md) already sets for an absent input; a rollback a human [marked as not caused by the release](../08-operations/03-overlapping-windows.md), evidence about something other than the author; and [a queue rejection whose repeated failure came with a moved dependency](../05-environments/03-the-merge-queue.md) — the two runs' compositions differing — evidence about the dependency and not the author. It is kept per model version and not per family, which is how a new version accumulates a prior of its own; the cost: moving a [fleet entry](../10-fleet/README.md) to a newer version starts its evidence over, and keeping the old name for a new version reads the old version's outcomes as the new one's. The [effort](../10-fleet/01-what-an-agent-runs-on.md) an entry runs at and the [role prompt](../10-fleet/03-what-an-agent-is-told/README.md) an agent works from change how one model behaves under one name too, and both are deliberately left out of the key — [_Paid for is not authored by_](../10-fleet/04-paid-for-is-not-authored-by.md) refuses the split and states what refusing it costs. Both are recorded on the vector a gate firing writes instead, which is where a fact a human argues with belongs. It starts wide for an author the factory has not seen and narrows with evidence — or starts at the prior the product shipped for that model version where it shipped one, which [_A model under a name_](../10-fleet/02-a-model-under-a-name.md) sets out with what a name pinned at the provider is worth, and with the one instrument the factory holds on a version that is not an outcome. A version that instrument finds departed from its own earlier results reads as an unfamiliar author, toward the gate — [the treatment a drifted factor takes](02-how-it-learns.md). The restriction [_The analysis window_](../08-operations/02-the-analysis-window.md) keeps — that only a rollback or a human's undo traceable to the [health monitor](../08-operations/01-the-health-monitor.md) counts — is that window's parameters' rule and not this one's: the window learns from what the [health monitor](../08-operations/01-the-health-monitor.md) could have seen, the prior from every outcome on that author's work, a change undone for being the wrong feature included, because building the wrong thing well says something about the author and nothing about the health monitor.
- **Exposure** — what the change reaches that the service did not reach before, read from the same diff: an outbound call added, a credential named or read, an authorization check removed or weakened, and a dependency change — the [build](../05-environments/01-records-and-one-long-lived-branch.md)'s resolved set diffed against the set of the service's [current release](../06-releases/05-the-deploy-record.md)'s build, each package added or moved named with its version and its declared licence, which reads an unpinned range resolving differently with nothing in the manifest changed as the change it is. Three things separate it from the change group. It only ever raises the number: a diff adding none of that reads as nothing, and nothing in this group lowers a score, its absence not being evidence of safety. It does not learn from outcomes: the signals [_How it learns_](02-how-it-learns.md) reads are misbehaviour signals, and a change that posts credentials outward moves neither error rate nor latency, so a [window](../08-operations/02-the-analysis-window.md) closing `cleared` on it says nothing about it — its weight is published and calibrated like the rest, and the only outcome that ever speaks to it is a later [advisory](../02-intent-into-items/01-intake/03-advisories.md), report, or undo, arriving on the prior and not on this factor. And it reads the diff and never the intent: an injected change and a mistaken one add the same call, which is what makes it the one factor a stranger's sentence in a [report](../02-intent-into-items/01-intake/02-reports.md) cannot talk its way past. Its evidence is a list on the vector — each call, each credential name, each check, each package with its version and licence, and the file and line of each — so what the human at [_Implementation_](../03-gates/07-what-particular-gates-decide/05-implementation.md) argues with is that list beside the diff [Work](../11-screens/01-work-ops-factory-people.md) renders. The list is not the diff, and where the two disagree the human decides over the code, the disagreement being what the list's derivation missed. It is derived by the factory from the diff and the build record, independent of the author, which is the condition test coverage failed above. What extracts a call or a credential read is per toolchain, as [_What a consumer declares_](../07-contracts/06-what-a-consumer-declares.md)'s derivation is, so where no extractor runs for a toolchain the factor is unavailable and resolves the way an unavailable factor does below — a human at the gate, the vector naming why — and never as nothing. What it costs: an extractor per toolchain to ship and keep, a human at Implementation on every change on a toolchain without one, and a residue the list states rather than closes — what an extractor misses is decided by nobody, and a change whose harm nothing observed narrows its author's prior like any other clean window.
- **Context** — what this change touches in this customer's business, and which sibling services consume what it publishes. The same diff is a different risk in a payments path than on a marketing page. The [intent](../02-intent-into-items/01-intake/README.md)'s source is here too, and one value of it is resolved rather than weighed: an intent grouped from [reports](../02-intent-into-items/01-intake/02-reports.md) takes, at the [Spec](../03-gates/07-what-particular-gates-decide/02-spec.md) gate, the treatment an unavailable factor takes below — a human at the gate whatever the formula returns, one the [held-out sample](02-how-it-learns.md) may not select past, resolution being what it already never overrides — because that channel is the one way in the factory cannot authenticate, which [_Reports_](../02-intent-into-items/01-intake/02-reports.md) states and owns.

A version of what an agent is told is scored on a set of its own, because the change group is computed from a diff and a [role prompt](../10-fleet/03-what-an-agent-is-told/README.md) has no code to have sized and no area to have churned. Three factors replace that group at [_A role prompt or a skill_](../03-gates/07-what-particular-gates-decide/09-a-role-prompt-or-a-skill.md) — the share of the factory working from this version; **departure**, how far it differs from the version in force; and reversibility, which is high for every version, [withdrawal](../10-fleet/03-what-an-agent-is-told/README.md) being a second record and nothing having been deployed. The author and context groups are unchanged, the author being the agent that wrote the version. That the set is different here rather than partly unavailable is the point: a factor the score cannot compute puts a human at the gate, and treating area churn as missing rather than as inapplicable would put one at every version forever — a decision nobody made, arriving as a side effect. One version has no author at all — the [shipped entry](../10-fleet/03-what-an-agent-is-told/README.md) an upgrade's first start enters, install's own firing no gate — and that absence is resolved rather than classed: a human at the gate whatever the formula returns, decided here so that a narrow shipped skill cannot auto-pass at an upgrade as a side effect. What it costs: a second factor set to publish, calibrate, and argue with, on a row that fires far less often than the eight of the [default path](../03-gates/03-actions-at-each-gate.md).

Likelihood and impact stay separate until the last step. They answer different questions and call for different responses: likely-wrong but cheap to undo should ship and let rollback handle it; unlikely but catastrophic should be gated regardless. This is also why one score decides three things about a change: the gate reads mostly likelihood against impact, the [rollout strategy](../03-gates/02-the-rollout-strategy.md) reads mostly impact against reversibility and how fast a problem would appear, and the boundary of the [_analysis window_](../08-operations/02-the-analysis-window.md) reads mostly impact. Reading different halves is what keeps them from weakening together: a change misjudged on likelihood, which is what a per-author prior and an unfamiliar area affect, loses its gate and keeps its watch.

Cost is not a factor and not a strategy input. A cost term would have the score trade a gate or a [control](../08-operations/01-the-health-monitor.md) for money, which [_How it learns_](02-how-it-learns.md) already refuses for the threshold: loosening it on cost alone is a judgment about what the factory is for, and the design hands that to the owner (8). The strategy is the same case: what a control costs is the owner's to weigh, and the levers are theirs — the [window limit](../08-operations/03-overlapping-windows.md), the [fraction of its instances a release keeps](../08-operations/03-overlapping-windows.md), and a [safeguard](../09-gate-policy/02-one-shape-across-all-of-them.md) on the strategy — where model spend has a lever of its own in the [spend ceiling](../10-fleet/08-a-spend-ceiling.md) an owner authors on a credential, which reaches nothing a control costs. The second reason is that there is nothing to calibrate a cost factor on: spend is recorded in the provider's units, which differ per model, so a factor over a fleet of two models would weigh units that do not add. What it costs: a large low-risk service pays a full control for every release the score gives one, and only a value an owner authored reduces it.

The defaults the score supplies where an owner authored nothing are not a fourth factor: [_Gate policy_](../09-gate-policy/02-one-shape-across-all-of-them.md)'s eight parameters are each a field of the record its scope names — a service, an area, an environment, or the factory-wide settings record — and seven of them move as outcomes arrive, where the three factors are computed from one change. They are fields of a **score version** — a row of the [decision log](../../deferred.md), appended by the log when the score calls for it and chained like every row there, naming the published formula, the factor set, and every value the score supplies, with a supplied value for seven of the eight rows and none for the [list of allowed predicate kinds](../07-contracts/06-what-a-consumer-declares.md), which no outcome teaches. Every decision names the version in force. Keeping the supplied value here rather than in the record that holds the authored one is what leaves both single-writer, and it keeps a [safeguard](../09-gate-policy/02-one-shape-across-all-of-them.md)'s floor distinguishable from the value moving inside it — one field two components wrote could not express that. The cost: a long sequence of versions, most differing in one number the decisions naming them never read, and a [value in force](../09-gate-policy/02-one-shape-across-all-of-them.md) that is a read of three things rather than one.

A version that differs in a supplied value having moved takes effect as it is appended — gating each would gate the learning itself. A version that changes the published formula or the factor set is a different event, because what an owner authors is compared against the number the published formula returns: under a changed formula the same change gets a different number, so the authored value would go on being displayed while meaning something else, and an owner who set a [risk threshold](../09-gate-policy/01-what-is-in-it.md) after an [incident](../08-operations/06-incidents.md) would hold a number the score had silently redefined under them. So such a version does not decide a gate an authored threshold binds until the owner has confirmed or re-authored that threshold against it (8), the version in force at those gates staying the prior one meanwhile — the arrangement [_A role prompt or a skill_](../03-gates/07-what-particular-gates-decide/09-a-role-prompt-or-a-skill.md) already gives a version nobody approved, which simply is not in force. What it costs: two score versions deciding at once while confirmations arrive, and an owner's silence keeping an improved formula out of force at their own gates indefinitely — the direction [_The interview_](../02-intent-into-items/02-the-interview.md) already accepts for a silence that spends nothing.

The vector is recorded where it was computed and never recomputed. A gate firing writes it onto that firing's [_decision_](../03-gates/01-where-a-gate-is-and-what-decides-it.md) beside the number, the score version, and the [policy version](../../what-the-factory-does.md#traceability), so every firing produces a vector of its own. Where an agent authored what is under decision, the vector also names the effort its entry ran at and the versions of the role prompt and the [skills](../10-fleet/03-what-an-agent-is-told/README.md) it worked from — the two facts the prior deliberately averages over, put where a human arguing with the number can see them, and where a query can group decisions by the version in force without any of it moving the prior. Recomputing one later reads today's prior, today's factor set, and today's formula — not the vector the decision was made on — and the vector a human argues with has to exist while they are deciding, which is why the decision is opened at the firing rather than at the verdict. At the four [artifact gates](../03-gates/01-where-a-gate-is-and-what-decides-it.md) the change factor is computed from the artifact under decision and at [Decomposition](../03-gates/07-what-particular-gates-decide/01-decomposition.md) from the set [decomposition](../02-intent-into-items/03-decomposition/README.md) proposed, so it is weakest exactly where the decision is cheapest to get wrong.

A factor the score cannot compute resolves to the value that puts a human at the gate, and the vector records which factor was unavailable and why rather than leaving a gap a reader has to interpret. That covers an input the score could not read, a [build](../05-environments/01-records-and-one-long-lived-branch.md) whose diff it could not take, and an evaluation that failed outright. The reason: the number is compared against a threshold, so a factor that silently reads as absent reads as low risk, and the gate a failure would remove is the gate that failure is evidence for needing. Nothing here decides how far the resolved value moves the number — that is the formula's, published like the rest of it — only its direction, which is the one thing that must not depend on a component being up. What it costs: a fault in whatever supplies a factor puts humans at gates across the factory at once, and from [_Work_](../11-screens/01-work-ops-factory-people.md) that looks like the score having changed its mind rather than an outage; what says otherwise is the vector on each decision naming the same unavailable factor, which is why the naming is not optional.
