# A role prompt or a skill

The first of two rows outside the default path and outside every item. What it decides is a version of what an agent is told — a [_role prompt_](../../10-fleet/03-what-an-agent-is-told/README.md) or a [_skill_](../../10-fleet/03-what-an-agent-is-told/README.md), authored by an agent from the factory's own decisions, or entered unauthored at an upgrade's first start — the one exception [_One pipeline_](../../01-one-pipeline.md) states, install's entries alone firing none — and written by the [artifact store](../../01-one-pipeline.md). Its actions are Approve, Reject with feedback, and Edit in place, which is what every authoring row offers, and for the same reason: what is under decision is a document, and a human who wants different words writes them.

There is no Hold, because a Hold would name a state the row is already in: a version not approved simply is not in force, and the one below it goes on being in force — or, for a chain an upgrade started, nothing is, and only the work that would have used it waits — where every other gate's hold exists to stop an event that would otherwise happen.

What it reads is the factor set [_Factors, at least_](../../04-risk-score/01-factors-at-least.md) names for a version, and its threshold is a field of the [factory-wide settings record](../../09-gate-policy/02-one-shape-across-all-of-them.md) rather than of an [environment](../../05-environments/01-records-and-one-long-lived-branch.md): there is no project here to have a production environment, and the row exists before any project does. A [safeguard](../../09-gate-policy/02-one-shape-across-all-of-them.md) (9) reaches it on subjects a safeguard may already name and no new kind: a [stage](../../01-one-pipeline.md) for a role prompt, a role prompt being per role and most roles naming the work of one stage — the [report store](../../02-intent-into-items/01-intake/02-reports.md) for [the grouper](../../02-intent-into-items/01-intake/02-reports.md)'s, its role being no stage's — and the [area](../../../what-humans-do.md), [service](../../02-intent-into-items/03-decomposition/README.md), or [project](../../11-screens/01-work-ops-factory-people.md) a skill is bound to for a skill. So an owner who has safeguarded an area already gets a human at every skill version written for it, without having asked for that twice.

Reject sends nothing back, there being no stage above this row to send it to, so [_Going back up_](../06-going-back-up.md) does not apply. What a reject leaves is a version nobody approved and the feedback that says why, which the next version is authored from — so [_the attempt limit_](../05-the-attempt-limit.md) does not reach this row — it counts a stage's attempts on an item, and there is neither. A factory that keeps authoring a version nobody approves keeps authoring it, and this is the one loop the limit does not close. What ends it is the evidence going away or an owner leaving the row alone, neither of which is a mechanism.
