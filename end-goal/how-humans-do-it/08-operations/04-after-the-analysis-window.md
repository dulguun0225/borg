# After the analysis window

The health monitor keeps running after the window closes, on the reading against the service's own recent history — the control was torn down with the window, so no comparison is left to run. What it finds then is not a rollback candidate — the change has been live for a week and the window's authority ended long before. It is an [unrefined](../02-intent-into-items/01-intake/README.md) intent in [_Work_](../11-screens.md#work-ops-factory-people), the same shape as the intent an end user's [_reports_](../02-intent-into-items/01-intake/02-reports.md) are grouped into (4, 5), taking the same [stages](../01-one-pipeline.md) and the same gates. That is the whole of "finds issues and fixes bugs": a [detector](../02-intent-into-items/01-intake/README.md) writes an intent, and [the pipeline](../01-one-pipeline.md) does the rest.
