# Incidents

An incident is a record on a production environment, written by the health monitor at the crossing — of its own boundary, or of a threshold an owner's safeguard set — against the release running there, whether or not that release's window is still open. The health monitor is the only component that reads production behaviour and knows which release and which deploy that behaviour belongs to, which is exactly what an incident points at; a human-written one would put a judgment where the design keeps arithmetic, and a human's judgment about live software already reaches production through the undo of a shipped change (10) and the page they may fire. A human's judgment about the incident's cause has a place too and it is not the incident: a rollback [marked as not caused by the release](03-overlapping-windows.md) is a record beside it, and the incident stands, because production was worse whatever made it so. It points at the deploy, the deploy at the release and at [the schema change it applied](../06-releases/05-the-deploy-record.md) where it applied one, the release at its item and its intent — so what caused an incident is answered by following those links, a change to the store included, the same links the release record answers from the other end. Its status advances to resolved when the crossing has stopped against what is running *and* what was raised from it has finished: a rollback stops the crossing and does not resolve the incident, production being still worse, which is what the hold and the page both say.

It is also what the health monitor keys its own deduplication on, before it calls [intake](../02-intent-into-items/01-intake/README.md): an open incident on this service and this release makes a further crossing an observation on it and never a second intent. What that costs: an incident points at the deploy that was running when it appeared and not always at the one that caused it — a consumer broken by its producer gets an incident on its own innocent deploy, and the item raised from it is what finds the producer.

The factory works the item it raised under the [attempt limit](../03-gates/05-the-attempt-limit.md) like any other. Exceeding that limit turns it into an escalation (12), the same Work row a stuck feature produces: a bug the factory cannot fix is not a different kind of stuck.
