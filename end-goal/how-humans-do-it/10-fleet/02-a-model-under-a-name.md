# A model under a name

The version an entry names is a name the provider serves behind and not a function it promises to keep: what answers under one pinned version moves when the provider changes how it is served, and the name does not. The [_per-author prior_](../04-risk-score/01-factors-at-least.md) is kept per version so that two authors are never averaged into one, and a version that drifts under its name is that averaging arriving anyway, with the wrong sign — a new model enters with a wide prior and is put in front of a human at more [gates](../03-gates/01-where-a-gate-is-and-what-decides-it.md), which is right, while a drifted one keeps the narrow prior it earned before the drift and is gated less at the moment it became worse. The outcomes on the version's work are the factory's only other instrument, and they read as a rate over as many items as a rate takes to move. So the factory holds one instrument that is not an outcome: an **evaluation set** per [role](../01-one-pipeline.md), a fixed set of tasks with known answers, shipped with the product as [what an agent is told](03-what-an-agent-is-told/README.md) is shipped — content and not a record, moved only at an upgrade, authored by nobody at the install. It is run against an entry's model where the entry is written or its model or effort changed, and again after every so many dispatches onto the entry, that count being a field of the entry the owner writes with the rest of it — the entry is the owner's record and the run spends the owner's credential, so how often to spend it is theirs and no default is supplied beyond the run at the write. The run is dispatched like a stage's work and spends through the entry's credential like one, and its result is a record keyed by model version, effort, and the set's version, written by dispatch, which performed it. What the score reads from it is the departure of a result from that version's earlier results on the same set — the reading [_How it learns_](../04-risk-score/02-how-it-learns.md) already makes for a factor whose distribution moved — and a version found departed takes the treatment a drifted factor takes: its prior reads as an unfamiliar author's, toward the gate, with the [factor vector](../04-risk-score/01-factors-at-least.md) on each decision naming why, until the evidence since the departure narrows it again. What it costs: spend on work that ships nothing, at a rate the owner sets; a set the provider may have trained on, which reads as a model that did not drift; a fixed set that measures the set and not the work, so a departure says the model changed and never in which direction; and a first run with nothing to depart from — the entry's first result is the baseline, and a model that arrived already drifted is caught by outcomes or not at all.

The other end of the same fact is a version that stops being served. An owner moves every entry naming it to its successor, and [_Paid for is not authored by_](04-paid-for-is-not-authored-by.md) says what a prior starting over on every entry at once does: the number rises and humans land at gates across the factory. The product ships a starting prior per model version, beside the evaluation set and the first role prompts, measured by [the builder](../../what-the-factory-does/05-what-the-customer-runs-it-under.md) on the builder's own work, and an entry naming a version the product shipped a prior for starts there rather than wide; the install's own evidence moves it from there as it would from wide, and a shipped prior never replaces evidence the install already holds, an upgrade seeding only the versions the install has none on. What it costs: a prior measured on the builder's work and not this customer's, narrower than the evidence justifies wherever the two differ; a version the builder never measured starting wide as before; and the one channel by which anything learned outside an install reaches it, stated in [_What the factory does_](../../what-the-factory-does/README.md) beside the tenancy decision it is the price of.
