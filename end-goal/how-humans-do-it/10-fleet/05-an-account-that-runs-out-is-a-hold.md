# An account that runs out is a hold

A personal account has a quota an organisation's agreement usually does not, so the fleet has a failure nothing else in the factory has: an agent stops part-way through a stage because the account it runs on is exhausted.

That is not the model failing, and it is a **[hold](../03-gates/04-what-a-gate-may-change.md)**. Nothing wrote it at a [gate](../03-gates/01-where-a-gate-is-and-what-decides-it.md), no gate having fired, so it is written into the [decision log](../../deferred.md) by the log, with whoever could not reach as the caller and the actor — an agent for its own model credential, the [deployer](../08-operations/01-the-health-monitor.md) for an environment's. It records the credential name and never a pointer to the entry or the environment record, which is what keeps true the rule that no record written for traceability points at a credential or a fleet entry: an owner may delete or re-credential an entry without changing what any past record says, where an environment record is kept for as long as the [deploy records](../06-releases/05-the-deploy-record.md) naming it. Work routes the row by resolving that name against [_People_](../11-screens.md#work-ops-factory-people). Dispatch is not its writer — it matched the entry before the failure and cannot see an account exhausted part-way through a stage — but it reads outstanding holds so it does not dispatch onto a credential already known unreachable, and dispatches again when a retry resolves. The stage waits and resumes when there is a credential to reach, counting nothing against [_the attempt limit_](../03-gates/05-the-attempt-limit.md) and teaching the prior nothing — the score learns from a reject and not from a hold, which [_What a gate may change_](../03-gates/04-what-a-gate-may-change.md) settles for gates and [_The analysis window_](../08-operations/02-the-analysis-window.md) keeps when it counts only a rollback traceable to the [health monitor](../08-operations/01-the-health-monitor.md) as evidence. How good an author is has to be measured from that author's work.

No [_page_](../08-operations/07-pages.md) fires for a model credential. Nothing deployed is worse for an exhausted account, which is the condition, so it waits in [_Work_](../11-screens.md#work-ops-factory-people), which shows the item stopped on it like anything else that is stuck. The one exception is on the other side of [seam 4](../../deferred.md): the credential for a [deploy target](../05-environments/01-records-and-one-long-lived-branch.md), held on that environment's record and never on an entry, that cannot be reached while the [health monitor](../08-operations/01-the-health-monitor.md) is calling for a rollback leaves production serving a [release](../06-releases/02-the-release-record.md) the factory has already failed, with no mechanism of its own left to improve it, which is the page condition word for word. It reaches whoever People records as having lent that credential. The same hold blocking a forward deploy pages nobody, a fix not arriving making nothing live worse. The drawback: the factory cannot see the balance it is spending against — a provider's remaining quota is not a field on the fleet entry, so exhaustion is discovered by reaching it and never predicted. What stops before it is [_A spend ceiling_](08-a-spend-ceiling.md), where an owner authored one, and that stops on the factory's own records rather than on the provider's.
