# Intake

What arrives is an **intent**: a request from an owner (1), the end-user [_reports_](02-reports.md) a grouper turned into one (4, 5), or something the factory found itself, raised by a **detector** — the [health monitor](../../08-operations/01-the-health-monitor.md) still running after its [window](../../08-operations/02-the-analysis-window.md) closed, a [consumer](../../07-contracts/01-two-versioned-things.md) breaking in its own error rate, a permanent [constraint](01-constraints-and-the-design-system.md) in force with shipped services inside its reach and no intent on its record, an [_advisory_](03-advisories.md) naming a package version a shipped [build](../../05-environments/01-records-and-one-long-lived-branch.md) resolved. One record, three sources, and one writer — intake writes every intent, and the three sources are three callers of one entrance rather than three components writing the same record. What it writes at that event is the source, the actor (seam 1 of [_Deferred, but not designed out_](../../../deferred.md)), whatever constraint arrived with the request and binds only what is decomposed from it, and for an intent the factory raised, a link to the evidence that raised it. An intent arrives unrefined, and nothing is judged on the way in, because judging it is what [the interview](../02-the-interview.md) is for.

It also writes the [project](../../11-screens.md#work-ops-factory-people) the request came in under, where a source supplies one — the project an owner raised it under, the project of the [service](../03-decomposition/README.md) a grouped report came from, or the project named in a detector's evidence. That field has one job: it is where [_Decomposition_](../03-decomposition/README.md) places a service the work creates, there being no existing service to reach a project through. It is not a claim about where the work is, because a [contract migration](../../07-contracts/02-no-single-item-may-break-a-contract.md)'s decomposed items may be in two projects, and it is not what scopes the constraints [_The interview_](../02-the-interview.md) reads. Where no source supplies one the field stays unwritten, and intake fills it once if decomposition has to place a created service and nothing else answers; it is never rewritten, so an approval keeps pointing at what was approved. Putting the project on the intent and not on the item is not a contradiction of [_What an item names_](../03-decomposition/02-what-an-item-names.md): an item names a service and reaches a project through it, and an intent names no service.

One writer costs a dependency edge from the far end of [the pipeline](../../01-one-pipeline.md) back to its start: [operations](../../08-operations/README.md) calls intake to raise what it found. What several writers would cost is one record's rules — the actor always populated, [the chain](../../../deferred.md), the links — implemented once per writer and drifting apart, on the record every other record links back to.

The intent is what [the graph](../../../what-the-factory-does.md#tight-integration) joins on. Every item links back to it, which is why one request producing four items in four services needs no record type of its own — the same point [_Work that spans services_](../../07-contracts/10-work-that-spans-services.md) makes from the other end.

The factory's own source repeats where the other two do not: a health monitor still running is still running tomorrow, and a consumer breaking in its own error rate goes on breaking. So a detector raises an intent for a condition and not for an observation — before raising one it looks for an intent on the same evidence that has not finished, and attaches to that one instead. The evidence is what keys it: this service, this consumer, this [contract](../../07-contracts/01-two-versioned-things.md), this [release](../../06-releases/02-the-release-record.md), this constraint — and for [_Deprecation_](../../07-contracts/08-deprecation.md)'s raises, the element, two marked elements of one contract being two removals. Keyed too finely it raises an intent per observation; too coarsely it attaches two problems to one intent, which decomposition then has to split.
