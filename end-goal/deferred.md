# Deferred, but not designed out

Two things are sequenced away rather than answered: security, and software the factory did not build. Both are decisions about order. What each has to satisfy is that waiting raises no price the factory cannot pay when it arrives, and the two satisfy it differently — security by leaving fields populated in the meantime, adoption by leaving nothing that has to be caught up in advance.

## Security comes last

The factory should be free and easy to play with at the start and tighten as the human world demands it. That is a sequencing decision, not permission to build something that cannot be secured later.

Four seams are nearly free now and expensive to retrofit:

1. **An actor on every record** — every gate decision, edit, approval, veto. No authentication, no enforcement, just the field, always populated. Identity cannot be added to a history that was written without it.
2. **One append-only decision log, each record chaining its predecessor.** It is the audit trail and the risk score's training data at once, and it must not become two systems. Append-only is a promise its writer makes about itself, and the chain is what makes it evidence instead — one field, populated from the first record. Where the head is anchored and who reads it can wait; the field cannot, because a chain laid over history written without one starts at the retrofit. The same record names the policy and the score version it was decided under, for the reason the actor is there: what a decision was made under is not recoverable from a history that recorded only the decision.
3. **Secrets by reference.** Artifacts and specs carry names, never values — they get copied, diffed, and handed to agents. So does the credential an agent reaches its own model through, which is [_The fleet_](how-humans-do-it/10-fleet.md) spending this seam before any artifact does. The resolver can be a file on disk today.
4. **A named seam between agents and deploy targets.** However it is implemented, an agent reaches an environment through a small set of named operations. That seam is where policy attaches later; without it, prod access is diffused through the codebase. What it attaches to on the other side is an agent's [_scope_](how-humans-do-it/01-one-pipeline.md), declared and enforced by nothing until this seam is spent.

One pipeline is not a fifth seam — it is the architecture the four attach to, and it was chosen for coherence rather than safety: a single path is a single place to put policy. What makes that place hold is that nothing routes around it, including incidents — the emergency lever [_One pipeline_](how-humans-do-it/01-one-pipeline.md) sets is approve now, not skip, so a rushed yes is a yes with an actor on it and not a hole. That is where most single-path designs come apart.

The cost is that a single path is a single blast radius. Almost nothing outside the pipeline disagrees with the pipeline, so a subverted one ships a change through the front door carrying a valid approval. What stands in for the second path is mostly downstream of the deploy and reads what the factory wrote: the log for detection, the actor for attribution, and veto after the fact (10) inside the [_watch window_](how-humans-do-it/08-operations.md#the-watch-window) for the undo. [_The reconciler_](how-humans-do-it/08-operations.md#the-reconciler) is the one thing that disagrees from outside, and it does so over a single fact — what is actually running against the record naming it — which is the whole of what a second path is worth buying separately.

## Adopting an existing codebase

Everything else in the tree assumes a factory that has always been there. A first run on software somebody else built has none of what that assumes, and how a factory takes such a codebase over is not designed here. What is settled is that it is sequenced away and what the wait costs, so that the section which eventually designs it starts from a bill rather than a discovery.

Five things a first run does not have, and what each costs until it does:

- **A deploy record for what is already running.** A service's [_current release_](how-humans-do-it/06-releases.md#the-number) is what its production deploy record names, and the factory made none of the deploys standing. Until it ships that service once, the dependency holds at both deploy gates and [_The reconciler_](how-humans-do-it/08-operations.md#the-reconciler) have nothing to read: the first deploy the factory performs is what brings a service inside its own checks.
- **Declared meaning on the interfaces.** [_What a diff cannot see_](how-humans-do-it/07-contracts.md#what-a-diff-cannot-see) prices this already — an interface adopted from outside arrives without it, and naming a field afterwards is a breaking change, which is three items for a rename no behaviour depends on. Until that is paid, a consumer's declarations are checked against what was never declared.
- **A design system a machine can read.** The screens exist and were drawn under no constraint the factory holds, so what enforces a look is a pin (9) putting a human at a gate — the cheap form [_Intake_](how-humans-do-it/02-intent-into-items.md#intake) sets out, costing that human for as long as the pin stands.
- **A build to stand a control from.** The factory can take traffic from what is running; it cannot stand up an instance set of a build it never made. So the first release on an adopted service is measured the way a straight deploy is, on the weak fallback [_The health signal_](how-humans-do-it/08-operations.md#the-health-signal) names, and the second release is the first one that can be measured properly.
- **History behind the learned parameters.** The authorship prior starts wide, K starts at 1, the item-size target and the watch window's size come from the score. That is the design working, and adoption is where its price is most visible: a service that has shipped for ten years climbs from the same floor as one that has never shipped at all.

None of those five is made unbuyable by waiting — each is paid at full price whenever adoption is designed, which is why this is deferred work and not a fifth seam. What no field populated on the first day recovers sits behind the adoption rather than in front of it: every release walks back to an item and its intent, and code the factory did not write walks back to the day it arrived and stops. That is not a deferred cost but one nothing could have bought, and what it means in practice is that an incident in adopted code is worked as an item like any other, while the walk out of it ends where the factory's own history starts.
