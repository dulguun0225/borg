# Enforcement

The rule is mechanical rather than a judgment call. The factory diffs the contract a candidate publishes against the one in production: a diff the contract's promise allows passes, and a breaking diff without the migration already shipped ahead of it is a rejection at the Merge to master gate. Which a diff is depends on the position of the element it touches, because compatibility runs one way for what an interface returns and the other for what it accepts. In output position an element added is compatible and one removed or redeclared is breaking. In input position an element added as required, an accepted range narrowed, an accepted value withdrawn, or an argument dropped is breaking, where an element added as optional or a range widened is not. The breaking edit in either position mints a major and takes the four items of a [migration](02-no-single-item-may-break-a-contract.md). The [consumer contracts](06-what-a-consumer-declares.md) in force are decided the same way in both positions: a candidate whose request form no longer accepts what a consumer's send-side predicate says it sends is rejected at Merge to master on the same terms as one whose response fails a read-side predicate. The [same graph](../../what-the-factory-does/01-tight-integration.md) answers who is affected — the factory knows which services consume which contracts, so "what does this break" is a query rather than an estimate, and it feeds the [context factor](../04-risk-score/01-factors-at-least.md) of the risk score directly.
