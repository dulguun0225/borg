# The six patterns

A criterion names the [requirement](../../../02-intent-into-items/02-the-interview.md) it answers, and this gate rejects in both directions over that field, mechanically and whatever the score returns: a requirement assigned to the item that no criterion in force for it names, and a criterion naming a requirement assigned elsewhere.

Criteria are predicates, not prose, for the reason a [consumer contract](../../../07-contracts/06-what-a-consumer-declares.md) is: what cannot be decided against an observed run is checked by nobody, and in the steady state that is most of them — the factory drafts its own criteria and a human reads them only where the score or a safeguard (9) puts one there. One source puts one there always. An intent grouped from [reports](../../../02-intent-into-items/01-intake/02-reports.md) has its source resolved rather than weighed, so this gate holds a human whatever the number is and no threshold an owner authors reaches it: the one floor this gate carries, owned by [_Reports_](../../../02-intent-into-items/01-intake/02-reports.md) and stated here because this is the gate it lands on. Each states one testable behaviour in one of a closed set of six sentence patterns, drawn from EARS.

| Pattern | The sentence it makes |
|---|---|
| **always true** | `the system shall <response>` |
| **event** | `When <trigger>, the system shall <response>` |
| **state** | `While <state>, the system shall <response>` |
| **unwanted condition** | `If <condition>, then the system shall <response>` |
| **optional feature** | `Where <feature is included>, the system shall <response>` |
| **state with an event inside it** | `While <state>, when <trigger>, the system shall <response>` |

Ids are stable and never reused, the same rule the [release number](../../../06-releases/04-the-release-number.md) keeps, and a criterion that is dropped stays withdrawn rather than freeing its id. The mechanism differs. The release number is an ordinal because ordering builds is its job, and its position in master's linear history is what lets [_The merge queue_](../../../05-environments/03-the-merge-queue.md) re-derive one after a stop or a restore from a backup. A criterion id orders nothing and nothing outside the factory records it, so it is opaque, drawn so that minting cannot repeat one, and a restore that loses criterion records rewinds no counter. What opacity costs is an id a human reads nothing from, which the release number's whole job is to provide. A sentence fitting no pattern is admitted with a tagged reason and counted: a form everything can escape is not a form.

A criterion may state a quality of the behaviour as well as the behaviour, a latency, a property of the rendered screen. The six patterns already carry one: the response clause holds the measurement, so `When the export is requested, the system shall respond within 200 ms under the stated load` is the event pattern like any other. What admits it is the rule that admits every criterion, decidability against an observed run, which for a quality criterion means its encoding produces the condition it measures on [the candidate environment](../../../05-environments/04-what-the-candidate-environment-decides/README.md): load the encoding generates, stated in the criterion's sentence, or a render the encoding drives and reads. An encoding whose load is stated leaves no unloaded run to disagree with a loaded one, so it goes [undecided](../../../05-environments/04-what-the-candidate-environment-decides/01-the-third-outcome.md) only the way any encoding does. What it establishes is bounded and named: behaviour on that environment's hardware under that load, which is not production's scale — production is read afterwards, by [the health monitor](../../../08-operations/01-the-health-monitor.md)'s comparison and by [an explicit threshold](../../../08-operations/01-the-health-monitor.md) a safeguard (9) sets, and [_Does the explicit health threshold link to what motivated it?_](../../../../open.md#does-the-explicit-health-threshold-link-to-what-motivated-it) is the question that residue leaves open. What it costs is the most expensive encoding kind there is: generated load and a driven render spend candidate compute at every run, and an owner whose complaint was production's scale has bought a check that cannot see it.

The check above narrows the incompleteness the form leaves and does not close it: a set answering every requirement assigned to the item can still be half a set, and nothing mechanical will ever ask for the unwanted conditions.

What is available instead of a check is a count, which is why the share of criteria written in the unwanted-condition pattern is one of the numbers Factory reports. Nothing decides on it and no gate reads it: a set with none is visible without anything having judged that it should have some. The cost: the number means little against one item, an item genuinely having none sometimes, so it is read across a service and over time rather than against a spec, and an agent that has learned it is counted can satisfy it with unwanted conditions nobody needed.
