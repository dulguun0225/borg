# The record

A criterion is a record of the service and the spec does not restate it. A restated criterion would let the spec and the criterion disagree, which is the reason an item names no [project](../../../11-screens/01-work-ops-factory-people.md), and it would make ids stable and never reused a rule about nothing. The record is written exactly once, by the [artifact store](../../../01-one-pipeline.md) in the same call that submits the spec version introducing it, and never written again. Withdrawal is recorded on the withdrawing spec version, so a version the gate rejects takes its withdrawal down with it.

A criterion's provenance has two sources and a default, read at introduction. **Constraint-derived** is a field the artifact store writes once, in the same call, where the drafting stage held a constraint record as its evidence. **Human-confirmed** is not a field but a query over the introducing spec version's [decision](../../01-where-a-gate-is-and-what-decides-it.md), which carries the actor and the resolved vector, the way in force is already a query. Everything else is factory-drafted. What that costs: a criterion whose introducing decision the [log](../../../../deferred.md)'s retention cut removed reads as unknown provenance, and unknown resolves toward the gate.
