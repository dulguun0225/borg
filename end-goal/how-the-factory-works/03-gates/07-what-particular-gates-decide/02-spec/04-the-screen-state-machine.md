# The screen state machine

Where the item has a user interface, the spec version introduces a screen's **state machine** — the states a screen can be in, the events that move it between them, and what each state forbids, empty and loading and failed among them. It is part of what a human confirms here (6) and not one of the six patterns: the patterns are sentences and lose the transitions, and it is the transitions that make [_Implementation_](../05-implementation/README.md)'s rejection mechanical. It is a record of the service like a criterion, written by the artifact store in the same call, and the screen's identity is the id of the state machine that introduced it. The id is per service, stable and never reused, the rule the criterion id and the release number both keep, and opaque by the criterion id's mechanism rather than the release number's. A revision is a new state machine naming the one it supersedes, and the chain of supersessions is the screen; there is no screen record, because a screen with no state machine is nothing the factory can check. Which are in force for a build is the query the criteria are read by, less those a machine in that build supersedes, and that set is what the [screen predicates](../../../05-environments/04-what-the-candidate-environment-decides/01-the-third-outcome.md) are decided against. The cost is that nothing mechanical stops two items introducing two chains for what a human would call one screen, and what catches that is the owner confirming here — the one place the flow's enforcement rests on a human noticing rather than on a link.

A superseding machine gets the same treatment where what it removes is protection: one that removes a forbidden transition a **human-confirmed** machine declared is a [resolved factor](../../../04-risk-score/01-factors-at-least.md) at this gate, routed the way a criterion's withdrawal is. Cost: one human decision per such revision.

The drawback is the authoring, the same one declared meaning has in [_What a diff cannot see_](../../../07-contracts/05-what-a-diff-cannot-see.md) — a sketch is cheaper and checks nothing. What the screen looks like is not here: that is the design system the project chose as a [permanent constraint](../../../02-intent-into-items/01-intake/01-constraints-and-the-design-system.md) (2), a screen design that arrived with the request and binds only what was decomposed from it, and, where neither answers, [_Implementation plan_](../03-implementation-plan.md).
