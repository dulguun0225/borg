# The transition check

Whether a program admits a transition is a question over its reachable states, not decidable in general, so every instrument for it approximates in a direction it has to state. The transition check is therefore a derivation from [the build](README.md) on the terms [_What a consumer declares_](../../../07-contracts/06-what-a-consumer-declares.md) sets: per toolchain, the extractor a component of the factory shipped with it, and which toolchains have one published as a fact of the factory's version. Its direction is fixed. It rejects only a transition it can show the implementation admits, from a state the [machine](../02-spec/04-the-screen-state-machine.md) declares, on an event it declares, to a state the machine does not declare from there on that event, the machine being closed and every undeclared transition forbidden. It never rejects on what it could not follow, and it enumerates that per screen: a handler registered at run time, a dispatch through a table, a state derived from data a server returns, a transition a third-party component performs. A screen with any such construct, a build no extractor covers, and an extraction that fails outright take one outcome, **could not derive** for that screen — a record, not an empty list, for the reason a consumer contract's non-derivation is one. It resolves the way an [unavailable factor](../../../04-risk-score/01-factors-at-least.md) does: a human at this gate whatever the formula returns, the [vector](../../../04-risk-score/01-factors-at-least.md) naming the screen and the constructs that defeated the analysis.

A partial extraction reads as none rather than as clean because the transition most likely to be forbidden is the one an agent made by routing around the declared constructs, which is exactly what a check skipping them would auto-pass. What it costs is the direction the consumer contract already takes: a human at Implementation on every screen of a toolchain the extractor follows only partly, standing pressure to extend the extractor or to build screens from the constructs it follows. The [design system](../../../02-intent-into-items/01-intake/01-constraints-and-the-design-system.md)'s components are such constructs, a system the factory ships arriving with its extractor. The residue is stated rather than promised away: a transition the analysis could not see is unprotected until a run exercises it. The [drivers](02-the-encoding-and-the-emission.md) and the [predicates](../../../05-environments/04-what-the-candidate-environment-decides/01-the-third-outcome.md) decided over rendered states are what exercises one, and past that a [safeguard](../../../09-gate-policy/02-one-shape-across-all-of-them.md) (9) on the area.
