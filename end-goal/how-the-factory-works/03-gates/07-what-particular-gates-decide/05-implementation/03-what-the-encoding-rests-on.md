# What the encoding rests on

Its authority comes from the gate rather than from the [encoding](02-the-encoding-and-the-emission.md) being faithful, the same arrangement [_What a consumer declares_](../../../07-contracts/06-what-a-consumer-declares.md) uses for an artifact the factory derived. The drawback: an agent that misread a [criterion](../02-spec/01-the-record.md) can encode its misreading and pass what it wrote. What limits that is the criterion a human confirmed (6) one gate up: it is unchanged, it is still the thing being checked, and an encoding that departs from it is rejected here like any other artifact that does not do what it was authored from.

That limit is weaker than it reads, because in the steady state the score auto-passes the Spec gate. An intent grouped from [reports](../../../02-intent-into-items/01-intake/02-reports.md) is the exception, its source resolving a human to that gate on its own, and the criterion was confirmed by nobody. So one rule governs the authoring: **an encoding's expected behaviour is derived from the criterion's sentence, never from the code it checks.**

The two are authored in the same stage by the same agent, and an encoding written by reading an implementation cannot disagree with that implementation — a defect in the code becomes the expected result, and the run that decides the criterion then passes on it. Reading the criterion first is the only independence available, the sentence being the one thing that existed before the code.

That rule is an instruction to the agent and not a check. What would make it a check is a decision procedure independent of the agent: a generator, a human-approved set of cases, an invariant over real data, or mutation of [the build](README.md). The first three cost authoring this stage lacks and stay refused. Mutation is adopted, costing compute and no authoring, which is the condition [_Factors, at least_](../../../04-risk-score/01-factors-at-least.md) sets for an author-independent measurement. At [the candidate run](../../../05-environments/04-what-the-candidate-environment-decides/README.md) the deployer mutates the lines the diff touches, re-runs the encodings naming criteria it reaches, and records the share of mutants detected, the mutation score, beside the criteria results. The mutation score is a reading on the build read at [_Merge to master_](../07-merge-to-master.md), not a factor of the risk score's [change group](../../../04-risk-score/01-factors-at-least.md); at every gate above the candidate run it is inapplicable rather than unavailable, the way exposure is inapplicable at every gate above this one. It is derived per toolchain, with a coverage field and a **could not derive** outcome like any build derivation; a service the factory cannot mutate reads could not derive, never passing, and takes the treatment that outcome already takes at Merge. A passing criterion still establishes only that an encoding of it passes; the reading says whether that encoding could have failed.
