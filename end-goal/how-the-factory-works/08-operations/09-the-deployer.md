# The deployer

The **deployer** is the component that creates and tears down [candidate environments](../05-environments/02-an-environment-per-candidate.md), performs every deploy, applies [a build's schema change](../06-releases/05-the-deploy-record/README.md) to its service's store before the build takes traffic, executes the [rollout](../03-gates/02-the-rollout-strategy.md), and writes [the deploy record](../06-releases/05-the-deploy-record/README.md). It reaches a [deploy target](../05-environments/01-records-and-one-long-lived-branch.md) through [seam 4](../../deferred.md), and no agent reaches one at all. What that costs: the deployer is the largest component in [the component graph](../../components.md), so one fault in it stops both deploying and undoing.

An agent's execution has a host, and [seam 3](../../deferred.md)'s resolver may be a file on that host: the claim that no agent reaches a [deploy target](../05-environments/01-records-and-one-long-lived-branch.md) is about what an agent was dispatched to today, not about what its execution could reach. That residue stands until [seam 5](../../deferred.md) is enforced.

[The build runner](../05-environments/01-records-and-one-long-lived-branch.md) is split off: the component that performs every build, reaching no deploy target and crossing [seam 4](../../deferred.md) never, since a build needs no target and no credential the deployer resolves. The split removes the cost [_Records, and one long-lived branch_](../05-environments/01-records-and-one-long-lived-branch.md) named: a component reaching an environment being called once per item where none is reached.

The rest stays one component. Environment composition, [rollout](../03-gates/02-the-rollout-strategy.md), and rollback remain the deployer's, because a further split would still leave deploy and undo together: a rollout and the rollback that undoes it share the fault domain whichever component performs them. Under [seam 5](../../deferred.md) the principal on an environment composition and on a production rollout is the same name, the deployer's own, so a [seam 4](../../deferred.md) policy is written over the named operation, composing an environment or executing a rollout, and never over the caller, since every call the seam admits carries that one name.
