# A model under a name

The version an entry names is a name the provider serves behind and not a function it promises to keep: what answers under one pinned version moves when the provider changes how it is served, and the name does not. The [_per-author prior_](../04-risk-score/01-factors-at-least.md) is kept per version so that two authors are never averaged into one, and a version that drifts under its name is that averaging arriving anyway, with the wrong sign. A new model enters with a wide prior and is put in front of a human at more [gates](../03-gates/01-where-a-gate-is-and-what-decides-it.md), which is right, while a drifted one keeps the narrow prior it earned before the drift and is gated less at the moment it became worse. The outcomes on the version's work are the factory's only other instrument, and they read as a rate over as many items as a rate takes to move.

So the factory holds one instrument that is not an outcome: an **evaluation set** per [role](../01-one-pipeline.md), a fixed set of tasks with known answers, shipped with the product as [what an agent is told](03-what-an-agent-is-told/README.md) is shipped — content and not a record, moved only at an upgrade, authored by nobody at the install. A run is performed exactly as a stage's work is: [dispatched](../02-intent-into-items/05-dispatch.md) onto the entry, working from the [role prompt version in force](03-what-an-agent-is-told/README.md) for the role and the skill versions whose subject a task matches, at the entry's effort, spending through the entry's credential. An instrument run under words no dispatch uses would measure a configuration that ships nothing.

Three things run it. The entry being written, or its model or effort changed. Every so many dispatches onto the entry, that count being a field of the entry the owner writes with the rest of it — the entry is the owner's record and the run spends the owner's credential, so how often to spend it is theirs and no default is supplied beyond the run at the write. And a role prompt version taking force, which runs the set once on every entry in that role.

Its result is a record keyed by model version, effort, role prompt version, the skill versions the run matched, and the set's version, written by dispatch, which performed it. What the [score](../04-risk-score/README.md) reads from it is the departure of a result from earlier results under the same key, and never across two keys; the reading is the one [_How it learns_](../04-risk-score/02-how-it-learns.md) already makes for a factor whose distribution moved. The words are in the key so that departure says the model moved and not that the factory revised what it is told: a role prompt version taking force starts a new baseline for each entry in its role, and the results before it are compared with nothing after it. A version found departed takes the treatment a drifted factor takes: the prior is resolved rather than weighed, a human deciding whatever the formula returns, with the [factor vector](../04-risk-score/01-factors-at-least.md) on each decision naming why — until the evidence since the departure narrows it again.

Two role prompt versions on one model version and one set are two results one key apart, which is what [_Reach is what decides one_](03-what-an-agent-is-told/02-reach-is-what-decides-one.md) has to read about a version, and all it has: the set measures the set, and whether a version made the work better stays [open](../../open.md#how-does-the-factory-learn-whether-a-role-prompt-version-is-better).

What it costs, in four parts. Spend on work that ships nothing, at a rate the owner sets on the entry and the factory sets at every role prompt version, counted against the credential's [spend ceiling](08-a-spend-ceiling.md) the way a stage's spend is, so a factory revising a role prompt often reaches the ceiling sooner. A set the provider may have trained on, which reads as a model that did not drift. A fixed set that measures the set and not the work, so a departure says the model changed and never in which direction. And a first result under each key with nothing to depart from — the first result is the baseline, and a model that arrived already drifted, or a role prompt version that made it worse, is caught by outcomes or not at all.

The other end of the same fact is a version that stops being served. An owner moves every entry naming it to its successor, and [_Paid for is not authored by_](04-paid-for-is-not-authored-by.md) says what a prior starting over on every entry at once does: the number rises and humans land at gates across the factory. The product ships a starting prior per model version, beside the evaluation set and the first role prompts, measured by [the builder](../../what-the-factory-does/05-what-the-customer-runs-it-under.md) on the builder's own work, and an entry naming a version the product shipped a prior for starts there rather than wide. The install's own evidence moves it from there as it would from wide, and a shipped prior never replaces evidence the install already holds, an upgrade seeding only the versions the install has none on. It enters as a supplied value on a chained [score version](../04-risk-score/01-factors-at-least.md) naming the [shipped-bundle identity](../../deferred.md#the-products-release-channel) it came from, never as an [install exception](03-what-an-agent-is-told/README.md): the score already supplies this value whether a starting prior shipped or not, so nothing here needs to run ungated. The install exception stays for the role prompt, the skill, and the evaluation set, which a fresh install has no version of yet, since a factory with nothing decided in it has to run; each such entry names the same identity, so an ungated entry says which bundle supplied it. What it costs: a prior measured on the builder's work and not this customer's, narrower than the evidence justifies wherever the two differ, and a version the builder never measured starting wide as before. The one channel by which anything learned outside an install reaches it is stated in [_What the factory does_](../../what-the-factory-does/README.md) beside the tenancy decision it is the price of.
