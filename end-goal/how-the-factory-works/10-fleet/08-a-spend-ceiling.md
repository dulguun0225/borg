# A spend ceiling

A **spend ceiling** is a limit an owner authors on what the factory spends through one credential, in the units the provider returns, over a stated period that rolls forward the way the [error budget](../08-operations/05-service-level-objectives.md)'s does, and reaching it before the period ends is a [hold](../03-gates/04-what-a-gate-may-change.md). It is authored on the [_People_](../11-screens/01-work-ops-factory-people.md) declaration that records who lent the credential, which is already per credential name and owner-written, and it has no default: where none is authored the credential is unbounded, Factory names it so, and the provider's quota is the only stop, which is what every install had before. The credential is the scope because it is where the money is: one credential is one account at one provider and one invoice, where an entry, a stage, or an area each draw on accounts whose invoices are separate. It reaches a model credential only, since what is recorded is what a run spent. Authored on the credential an environment reaches its targets through, it compares nothing, because a deploy records no spend. What the scope costs: a credential carrying two models sums units the provider prices differently, so the ceiling is exact on a credential running one model and a bound on units rather than money otherwise — an owner who wants it exact lends one credential per model.

What it is compared against is the [agent run record](01-what-an-agent-runs-on.md) every run of an agent already writes, which carries the credential name, the units the provider returned, and the period they fall in. The sum the ceiling compares is a query over the run records naming that credential within the period, and it reads nothing at the provider. That is the construction [_the attempt limit_](../03-gates/05-the-attempt-limit.md) uses when it compares against the item's own count rather than the log, so the fleet storing a reference and not a balance is no obstacle, since no balance is read. What a stage spent and what [the interview](../02-intent-into-items/02-the-interview.md) spent are each the same query narrowed to the runs that stage or that round performed, so an item's total and an intent's derive by joining the run records back to the stage or round that performed them, rather than being written a second time. An [evaluation set](02-a-model-under-a-name.md) run's record carries the same credential name and enters the same sum with the rest; a run the factory triggers at a role prompt version is spend the owner did not schedule, and the ceiling is what bounds it.

There is no reservation: dispatch does not hold units aside before a stage starts. The agent reports units as it works, and the ceiling is compared at each report; where a report would put the sum past it, the hold is written mid-stage by whoever could not proceed — the row [dispatch](../02-intent-into-items/05-dispatch.md) keeps for a ceiling met there, the same shape it keeps for a credential exhausted part-way through a stage.

Cost per feature is the same record read the other way: the intent's own run records plus the run records of the items [decomposed](../02-intent-into-items/03-decomposition/README.md) from it, reading no fleet entry and no account, the credential name resolving nothing, so the substrate a human wrote is never read. It is reported per model version, in the units the provider returned, and converted at the write wherever the owner authored a rate on the [_People_](../11-screens/01-work-ops-factory-people.md) declaration: a rate is the owner's agreed price and not a fact read from the provider, the same kind of owner-written fact as the ceiling beside it. Where a rate covers every model a feature's stages ran on, cost per feature sums to one total across them. Where one is missing, the reading stays per model version with no total, because a feature's stages run in more than one role and a role may run on a different model. What that costs: a feature on a fleet of two models with no rate authored has two numbers and no total, and a human authoring a stage instead of an agent spends nothing the factory can see. The ceiling stays in the units the provider returns and is never converted: it bounds what a credential may spend and not what that spend is worth.

Reaching the ceiling before its period ends is the hold [_An account that runs out is a hold_](05-an-account-that-runs-out-is-a-hold.md) describes, written the same way and routed to the owner rather than to whoever lent the credential, since raising, clearing, or lengthening the period is the owner's and a row reaching the lender would reach somebody who cannot act on it. It is written into the [decision log](../../deferred.md) by the log, naming the credential, with no [_page_](../08-operations/07-pages.md), no attempt counted, and the prior taught nothing. [Dispatch](../02-intent-into-items/05-dispatch.md) puts nothing further onto that name until it clears, writing a hold of its own per item it declines, so that twelve items waiting on one ceiling are twelve rows in Work and a count at Factory rather than one row naming a credential and no item. The owner clears it at [_Work_](../11-screens/01-work-ops-factory-people.md), and a clear authorises an overage for that period only: it does not reset the sum, and the same units stop the next period at the count authored for it. The ceiling is units over that stated period rather than a total since the last clear, on the precedent the error budget already sets for reading a calendar. Factory notifies at a fixed fraction of an authored ceiling and of nothing else, so the hold is not the first anyone hears of it.

It is not one of [gate policy](../09-gate-policy/01-what-is-in-it.md)'s eleven. Every row there has a value the score supplies and a safeguard narrows. The score learns from rollbacks and the changes humans undo, and a ceiling's evidence is cost, which the score does not read. So there is nothing to supply and nothing to safeguard, and it is authored outright, beside the [service level objective](../08-operations/05-service-level-objectives.md) and the [fraction of its instances a release keeps](../08-operations/03-overlapping-windows.md), which [_What is not in it_](../09-gate-policy/03-what-is-not-in-it/README.md) lists.

What it costs: a stop a human has to clear. It bounds model spend and nothing on the host — the [environment per candidate](../05-environments/02-an-environment-per-candidate.md) and the fleet a release keeps are hosting the owner pays for outside the factory, so the ceiling bounds the provider's invoice and never the hosting one. It is compared at each report rather than only at a stage's end, so overshoot is bounded to one report's worth of units; a stage that stops without ever reporting still spends unseen until its account is next reached. Two entries on one account under two names are two ceilings over one quota, and only the owner knows they were one. And it reads agent work alone, a human's stage spending nothing it can see.
