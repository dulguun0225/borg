# A fleet proposal

The factory does not write a fleet entry and does argue for one. A **fleet proposal** is a record it writes at [Factory](../11-screens/01-work-ops-factory-people.md): a set of entries to write and a set to retire, each naming a role, a model, an effort, and a scope, with the evidence behind it. It names no credential. Which account funds a model is the one thing the factory never chooses, and refusing to name one is what leaves [_What an agent runs on_](01-what-an-agent-runs-on.md)'s refusal standing rather than reopened.

Letting the factory write the entry itself was considered as the later step, one change to one writer rather than a second mechanism, and is refused until two things hold that do not. A [spend ceiling](08-a-spend-ceiling.md) is not bound enough, twice over: it has no default, so a credential nobody authored one on is unbounded with only the provider's quota as a stop, and it bounds magnitude and never allocation. Writing a model and an [effort](01-what-an-agent-runs-on.md) onto an entry chooses whose lent account runs and on what, an authority the lender consented to an owner holding, not the factory. What would lift the refusal is a bound that holds on every credential with nothing authored, and a lender's consent covering the factory's allocation. What the refusal costs is that every fleet change waits on an owner, and a proposal can wait unread — the gap already named below.

Two occasions write one. At first start, and at an upgrade's first start where a stage was added, the **install's first-start step** writes a proposal covering every role: an entry for each, drawn from the shipped starting priors and the shipped [evaluation sets](02-a-model-under-a-name.md) rather than argued. It follows the precedent already set for a role prompt nobody at the install authored: the authoring-nothing arrangement [_What an agent is told_](03-what-an-agent-is-told/README.md) states for the shipped prompt entry an upgrade enters. The owner opens it at [Factory](../11-screens/01-work-ops-factory-people.md) like any other proposal, and nothing pages. Every other proposal is argued, which is what the rest of this section describes.

A proposal argues over the fleet and not over one entry. It may say that five entries should be retired and six written in their place, because a fleet shaped wrong is not repaired by adding to it, and a mechanism that could only add would recommend growth for as long as anything was wrong.

Retiring costs nothing the design has to protect. No record written for traceability points at a fleet entry — [_An account that runs out is a hold_](05-an-account-that-runs-out-is-a-hold.md) records a credential name and never a pointer, for this reason among others — so an entry deleted changes nothing any past record says. The prior survives too, being per model: [_A credential taken back_](06-a-credential-taken-back.md) already says a fleet rebuilt keeps every bit of its history, and a fleet redesigned keeps it on the same grounds.

Its writer is not a [detector](../02-intent-into-items/01-intake/README.md). A detector is one of three callers of [intake](../02-intent-into-items/01-intake/README.md), and intake writes every intent; a component that also wrote a record of another kind would be a second writer with no [seam](../../deferred.md) between the two things it wrote. So a proposal has a writer of its own, and the record has two writers with a field as the seam: the factory writes the proposal and never its **disposition**, an owner writes the disposition and never a proposal. A disposition is open, accepted, or dismissed. Without one nothing would ever be finished, and the rule a detector keeps would have nothing to test. That rule is to raise for a condition rather than for an observation, attaching to what has not finished instead of raising a duplicate, so a shortage that lasted a month would produce a month of proposals. The **install's first-start step** writes on the proposal half of that seam without becoming a second writer of the same kind. It writes the proposal only at a version's first start, at an install's first start or at an upgrade's first start that added a stage, and every other write of the proposal side is [dispatch](../02-intent-into-items/05-dispatch.md)'s, performing the run of the role below.

The argued proposal takes [the grouper](../02-intent-into-items/01-intake/02-reports.md)'s treatment, for that section's reason: composing one is model work, and model work outside [the fleet](README.md) would run on words no gate ever decided. Arguing a proposal is a role of its own, put on neither an intent nor an item, running under a fleet entry an owner writes like any agent, at that entry's model and effort and through its credential. Its [role prompt](03-what-an-agent-is-told/README.md) is versioned and decided at [the gate every version fires](../03-gates/07-what-particular-gates-decide/09-a-role-prompt-or-a-skill.md), where [reach](03-what-an-agent-is-told/02-reach-is-what-decides-one.md) puts a human at every role prompt version, so the words that compose what an owner reads are decided the way every agent's are. [Dispatch](../02-intent-into-items/05-dispatch.md) performs the run and writes the proposal, the way it writes an [evaluation-set result](02-a-model-under-a-name.md). What it costs is twofold. An owner writes a fleet entry for the role before the factory can argue at all: a fleet with none has the first-start proposal, [the readiness reading](../11-screens/01-work-ops-factory-people.md), and dispatch's holds, and no argued proposal. And the record arguing the fleet should change is composed by an agent the current fleet runs — the shape [_Reach is what decides one_](03-what-an-agent-is-told/02-reach-is-what-decides-one.md) already names for a role prompt authoring its replacement, answered the same way, the disposition being the owner's.

What occasions a run is the rule the disposition above exists to test. Dispatch performs it on a pass of its own, reading the evidence already on the record: its own holds, [the readiness reading](../11-screens/01-work-ops-factory-people.md), and [_Factory_](../11-screens/01-work-ops-factory-people.md)'s rates. A proposal attaches to the condition it argues over, so a shortage that lasts a month is one open proposal and not a month of them. The pass overwrites a [last check](../08-operations/08-drift-detection.md) of its own, carrying its interval, so a pass that stopped is a named row on [the home view](../11-screens/02-three-properties-every-screen-needs.md) rather than a fleet nobody argues for.

There is no gate. Nothing ships from a proposal and nothing is decided by it: the owner's write is the review, and what that write produces is an entry [dispatch](../02-intent-into-items/05-dispatch.md) matches against, reviewed at a gate the way every other authorship is. That is [_Dispatch is a match, not a judgment_](../01-one-pipeline.md)'s argument one level up.

What a proposal may argue is wider than what an owner may do with it. A proposal for a new role is a proposal for a new [stage](../01-one-pipeline.md), and stage definition is outside everything an owner authors, where [_What is not in it_](../09-gate-policy/03-what-is-not-in-it/README.md) puts it, so nobody at this install can enact one, and it reaches the owner as something to take to whoever builds the factory. Free-form argument is what makes a redesign expressible at all; this is what it costs, and the cost is real, because the shortages a factory notices soonest are the ones no existing role covers.

The larger cost is that nothing scores the obligation to read one. Composing the fleet is substrate rather than one of [the twelve](../../what-humans-do.md), so a proposal waits at Factory until an owner opens it, and no [_page_](../08-operations/07-pages.md) fires, because nothing deployed is worse for a fleet that is too small. An unmatched item is not that same gap: it adds no new state and needs no new count, since [dispatch](../02-intent-into-items/05-dispatch.md) already writes the hold naming the cause and [_Factory_](../11-screens/01-work-ops-factory-people.md) already counts it there, and a per-role [readiness reading](../11-screens/01-work-ops-factory-people.md) reports the same shortage before any item has reached it. What nothing scores is narrower: whether anybody reads the proposal that would fix the shortage, and no number says how long one has waited unopened. That is the gap [_What the fleet is not_](09-what-the-fleet-is-not.md) already names for a credential nobody lent.
