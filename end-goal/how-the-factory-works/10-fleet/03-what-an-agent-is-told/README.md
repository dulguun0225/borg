# What an agent is told

An agent works from words as well as from a model, and the words are the factory's. [_What is not in it_](../../09-gate-policy/03-what-is-not-in-it/README.md) puts them there already, what is between the gates being the factory's own and an owner authoring none of it, without saying who writes them or what happens when they change. Three records do, and what separates them is how far each reaches.

A **role prompt** is what an agent in a role works from. There is one per role, so the set is closed the way the set of roles is: a role names the work of one [stage](../../01-one-pipeline.md), of the two put on an [intent](../../02-intent-into-items/01-intake/README.md), of [the grouper](../../02-intent-into-items/01-intake/02-reports.md), or of the role that argues [a fleet proposal](../07-a-fleet-proposal.md), and all of them are the factory's own.

A **skill** is a procedure an agent is given where the [item](../../01-one-pipeline.md) it was dispatched onto matches the skill's subject — an [area](../../../what-humans-do.md), a [service](../../02-intent-into-items/03-decomposition/README.md), or a [project](../../11-screens/01-work-ops-factory-people.md), which are the same lines a scope is drawn on. The set is open, and it is what the factory adds to when it learns something worth keeping about one part of the software rather than about one stage of the work.

A **selection rule** is what [context assembly](../../01-one-pipeline.md) selects by where the material a stage hands an agent exceeds what the entry's model reads at once: which kinds of material go first, how each is cut, and what is left out. There is one, for the whole factory, because what it reaches is every dispatch. Where no version is in force, assembly gives what fits in arrival order and records the rest excluded on the [input manifest](../../01-one-pipeline.md), the way the [score](../../04-risk-score/README.md) supplies a value nobody authored, so no item waits on it.

None of the three is a file. [_What the factory does not build_](../../../what-the-factory-does/04-what-the-factory-does-not-build.md) divides the world on exactly that question, a thing that stores bytes coming from outside and a thing the factory has to be the only writer of being the factory's, and these are the second kind. Their writer is the [artifact store](../../01-one-pipeline.md), which already implements the version chain, the versions of one thing in the order they arrived, the [actor](../../../deferred.md), and the authorship attribute once rather than once per author, and which gains another caller in the agent that authors a version.

A version is never edited. Correcting one is a withdrawal and a second version, the way a [constraint](../../02-intent-into-items/01-intake/01-constraints-and-the-design-system.md) already works and for its reason: what an agent worked from when it authored a stage is then reconstructible from arrival and withdrawal alone. Which version is in force is not a field either — it is the newest version of the chain that its [gate](../../03-gates/07-what-particular-gates-decide/09-a-role-prompt-or-a-skill.md) approved and nobody has withdrawn, a version not approved being not in force with the one below it in force still — nothing at all where an upgrade started the chain — and the entries install wrote standing without an approval, a factory with nothing decided in it having to run — and a field saying so would be one fact in two places able to disagree.

Withdrawal is also the undo, and it is the cheapest one the factory has. A role prompt that made things worse is withdrawn and the version below it is in force at the next [dispatch](../../02-intent-into-items/05-dispatch.md): no [rollback](../../06-releases/06-rollback.md), no revert item, no [last known-good release](../../08-operations/03-overlapping-windows.md), and no queue held behind it. It is cheap because nothing was deployed, and that is the same fact [_Reach is what decides one_](02-reach-is-what-decides-one.md) reaches for when it says nothing measures a version either.

The first version of each ships with the product rather than being written by anybody. That is the arrangement [_Constraints and the design system_](../../02-intent-into-items/01-intake/01-constraints-and-the-design-system.md) already names for content the factory supplies, and the factory's own first authored version supersedes it in the chain. An upgrade that changed the shipped words moves nothing by itself: at the factory's first start on the new version, what shipped enters the chain on the same authoring-nothing call that entered the first version at install — the artifact store writing it, the author field empty as the exception [_One pipeline_](../../01-one-pipeline.md) states — and it enters as a version awaiting [the gate every version fires](../../03-gates/07-what-particular-gates-decide/09-a-role-prompt-or-a-skill.md): a version not approved is not in force, so where it extends a chain the words the install ran on stand until the gate decides, and where it starts one — the role or the skill an upgrade adds — nothing is in force until then, only the work that would have used it waiting: a new role's items undispatched in [_Work_](../../11-screens/01-work-ops-factory-people.md), [dispatch](../../02-intent-into-items/05-dispatch.md) matching nothing whose prompt has no version in force, and an item matching a new skill's subject running without it. The install's entries alone enter in force ungated — a factory with nothing decided in it has to run, the acceptance [_Gate policy_](../../09-gate-policy/README.md) already makes for the values the score supplies. What decides it is the gate every version fires, and an empty author is a factor the score cannot compute, resolved the way [an unavailable factor](../../04-risk-score/01-factors-at-least.md) always is — a human deciding whatever the formula returns — so the changed words of a shipped role prompt or skill reach force through a human whichever way its reach alone would have gone. The same event makes [_Constraints and the design system_](../../02-intent-into-items/01-intake/01-constraints-and-the-design-system.md) write a withdrawal-and-arrival pair; a role prompt has the version chain and a gate a constraint does not, so here the gate is the answer. What it costs: an install nobody upgrades runs on what it was shipped with, nothing on any screen distinguishes a role prompt the factory chose from one it was given, and an upgrade adding a stage stops every item reaching it until a human decides the shipped words and writes a fleet entry for the new role — no page fires and no attempt counts while they wait, and both ends of the wait are at [_Factory_](../../11-screens/01-work-ops-factory-people.md). What the upgrade does not cost is the diagnosis: [dispatch writes a hold per stopped item](../../02-intent-into-items/05-dispatch.md) naming which of the two records is missing, so the stall reaches Work on each item and Factory as a count under that cause, on the same screen the version and the entry are written.

Each of the install's entries names the [shipped-bundle identity](../../../deferred.md#the-products-release-channel) it entered under, so the ungated entry says what release wrote it.
