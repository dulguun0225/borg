# A control above a release

A control started above a release runs the release [a rollback of it would return to](../../08-operations/03-overlapping-windows.md) — the newest release below it whose window closed without [failing](../../08-operations/02-the-analysis-window.md) it, past every release a rollback would descend past, and not the ordinal predecessor. The two coincide until something is failed and differ exactly after a rollback: master is linear, so the ordinal predecessor's build contains the change just failed, and a control on it would restart failed code onto organic traffic for the whole of the next window and measure the revert against the build it exists to remove. Defining both by one rule is what [_Overlapping windows_](../../08-operations/03-overlapping-windows.md) needs so that the build the comparison is made against and the build a rollback returns to are the same one, and neither is something the factory has already ruled out. What that costs is a dependent whose producer is mid-rollout waiting for it, which on a [widening schedule](../../03-gates/02-the-rollout-strategy.md) is the length of the rollout.
