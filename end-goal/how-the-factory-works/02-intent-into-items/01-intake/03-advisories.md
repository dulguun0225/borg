# Advisories

An **advisory** is a published statement that a named version range of a third-party package has a vulnerability, and the fourth [detector](README.md) reads them. The feed it reads is a thing from outside, on the far side of the division [_What the factory does not build_](../../../what-the-factory-does/04-what-the-factory-does-not-build.md) draws — a store of advisories somebody else keeps, one per package registry the factory's services resolve from, named by the owner the way a deploy [target](../../05-environments/01-records-and-one-long-lived-branch.md) is. What it is read against is a field of the [build](../../05-environments/01-records-and-one-long-lived-branch.md): every package a build resolved and the version it resolved to, written by [the builder](../../05-environments/01-records-and-one-long-lived-branch.md) from the build it performed. The condition is mechanical and no model reads a word of it: an advisory names a package and a range, a service's [current release](../../06-releases/05-the-deploy-record/README.md) names a build, and the build's resolved set holds that package inside that range. The detector reads the feed on a pass of its own, the way the conformance raise in [_Constraints and the design system_](01-constraints-and-the-design-system.md) reads the constraints in force, and calls intake once per advisory that matches anything.

Each of the two passes writes a [last check](../../08-operations/08-drift-detection.md) of its own each pass, carrying its interval, so a pass that stopped is a named row on [the home view](../../11-screens/02-three-properties-every-screen-needs.md) — without one, a stopped raise leaves the numbers clean, no window crossing and no gate firing, exactly as the absence of the raise would. The evidence is the advisory, which keys the raise, and [_Decomposition_](../03-decomposition/README.md) enumerates the services whose current release resolves it, an item to each, like the reach of a constraint. The intent it raises carries its own age, the time since the raise, which the [remediation period](../../09-gate-policy/02-one-shape-across-all-of-them.md) is read against. The condition follows the conformance raise's stricter rule: it stands until the intent exists, and an intent that ended is not raised over again, an advisory the owner dropped staying dropped until they ask. An advisory the feed withdraws ends it.

The same match runs a second time, earlier, over the [build](../../05-environments/01-records-and-one-long-lived-branch.md) rather than a shipped release: at [_Implementation_](../../03-gates/07-what-particular-gates-decide/05-implementation/README.md), on the terms a build-kind [constraint](01-constraints-and-the-design-system.md) already takes, the candidate's own resolved set is diffed against the feed and rejects there rather than waiting to raise an intent. It rejects only a package the change added or moved: a package already on master before the item started is not this read's business, and a match the change did not introduce reads as nothing at [_Implementation_](../../03-gates/07-what-particular-gates-decide/05-implementation/README.md). The bound is the [advisory severity](../../09-gate-policy/01-what-is-in-it.md), a gate-policy (8) parameter an owner authors or the score supplies; [_Deploy to production_](../../03-gates/07-what-particular-gates-decide/08-deploy-to-production.md) holds on the same bound over the release already merged.

The match is keyed by the source beside the name. The feed is one per registry, and each entry of the set records the registry or repository it was resolved from, so an advisory matches an entry only where the registry the feed speaks for is the source the entry names. One name in two registries is two packages: an advisory for one raises nothing over a service that resolved the other, and a service that resolved a package from a registry no feed is named for is listed as unassessed for it, never as clear. Without the key the match raises intents over packages a service never resolved and misses the substituted package, which is the shape a dependency-confusion attack takes.

The trust boundary is where it is for a [report](02-reports.md), and narrower. An advisory is a stranger's text arriving through a source the factory does not authenticate, and it reaches an agent only as its machine-readable match: the package, the range, the identifier. Its prose reaches the human at [_Work_](../../11-screens/01-work-ops-factory-people.md) and nobody else, so an advisory-raised intent carries no stranger's text in its evidence and is weighed rather than resolved. What separates it from a report is also that the match is decided against a record the factory wrote before any model reads a word: an advisory raises nothing unless a shipped build resolved the package it names. A lying feed can still move a version the factory did not need to move, or, with the hold at [_Deploy to production_](../../03-gates/07-what-particular-gates-decide/08-deploy-to-production.md), hold a deploy; what bounds it is a human who can approve through and the registries an owner chose to watch. What this costs: the agent plans a version move from a range and never from a description, on the manifest the entry's [requiring edge](../../05-environments/01-records-and-one-long-lived-branch.md) reaches, and where the chain reaches no manifest the service holds, the move is of the entry that requires it.

What the raise buys is the match and not the judgement. Whether the vulnerable path is reached by the service's own code is decided by nobody mechanical — the item ships the version the advisory clears, or a human ends the intent as dropped at [_Work_](../../11-screens/01-work-ops-factory-people.md), the end [_The interview_](../02-the-interview.md) gives one. It reaches Work as an unrefined intent and never as a [page](../../08-operations/07-pages.md) on the raise: the factory does not page to inform, and the advisory's severity travels on the evidence for a human to read there. Passing the [remediation period](../../09-gate-policy/02-one-shape-across-all-of-them.md) is not the raise, and it does page, on the ground [_Pages_](../../08-operations/07-pages.md) already gives a statutory deadline: worse on its own. What it costs is a resolved set on every build, repeated across rebuilds of one item, and a pass reading a feed the factory does not keep. It also states a gap rather than closing it — the detector reads advisories and not code, so a vulnerability nobody has published is invisible to it, and so is the interval between publication and the named feed carrying it. A candidate not yet shipped is read only once it is a current release, on the next pass after it becomes one. A registry with no feed named is not watched, and which registries are is a list on [_Factory_](../../11-screens/01-work-ops-factory-people.md) beside the constraints in force. Without the detector, nothing in the factory observes a vulnerability in something already shipped: the numbers are clean, no window crosses, no gate fires, and the only route from an advisory to a fix is an owner reading it and typing a request — work assigned to nobody and counted nowhere.

A match is decided only inside what the build's resolver covered, which the [build](../../05-environments/01-records-and-one-long-lived-branch.md) records beside the set: the ecosystems read, whether the base image, vendored source and statically linked code were enumerated, and which entries are present at run time. No advisory matching is therefore not a clearance. A service whose current release's set is **could not derive**, or whose coverage leaves out something a watched feed speaks to, is listed on [_Factory_](../../11-screens/01-work-ops-factory-people.md) as unassessed, beside the registries watched, and never counted among the services no advisory matched. An advisory naming a package the set holds as build-time only still raises, the entry's field travelling on the evidence for the human at Work to end the intent on. What it costs is a list of unassessed services that on an adopted estate with an uncovered toolchain is most of it, which is the reading the [consumer contract](../../07-contracts/06-what-a-consumer-declares.md)'s non-derivation already takes: weak protection reported as weak, and standing pressure to add the resolver.

The product's own release carries a resolved set of the same shape, as [_The product's release channel_](../../../deferred.md#the-products-release-channel) states, and the same pass matches it against the feeds. Its match is a row on [the home view](../../11-screens/02-three-properties-every-screen-needs.md) and never an intent, no item being cuttable for software the factory does not build, and it stands until an upgrade removes the match.
