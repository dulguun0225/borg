# Retirement

A service ends the way it began, by an owner's write on its record, and nothing else ends one. The owner writes **retired** at [_Factory_](../../11-screens/01-work-ops-factory-people.md), and the write is refused while a [consumer contract](../../07-contracts/06-what-a-consumer-declares.md) in force names the service, while an unmerged [item](../../01-one-pipeline.md) names it, or while an unmerged item's declared dependency points at it. What depends on the service is moved off it first, through the migration [_Deprecation_](../../07-contracts/08-deprecation.md) sets out, so a retirement never orphans a consumer and never strands work in progress. The write calls [the deployer](../../08-operations/09-the-deployer.md), which performs a **removal**: it ends every instance of the service on every target of every persistent [environment](../../05-environments/01-records-and-one-long-lived-branch.md), through the operation of seam 4 of [_Deferred, but not designed out_](../../../deferred.md) that ends instances, and writes a [deploy record](../../06-releases/05-the-deploy-record/README.md) per environment naming no release, complete per target as the instances there end.

That record is what changes what every reader reads. [Current release](../../06-releases/05-the-deploy-record/README.md) is read from the newest complete deploy record, and a removal's names none, so a retired service has no current release. A declared dependency on it would hold at both deploy gates, which none can by the refusal above, and a [candidate environment](../../05-environments/02-an-environment-per-candidate/README.md) composed for a dependant is composed with nothing for it. [The drift detector](../../08-operations/08-drift-detection.md) reads the removal as intended state, so an instance still running on a target is a mismatch. [The health monitor](../../08-operations/01-the-health-monitor.md), the [advisory](../01-intake/03-advisories.md) detector, and the pass over [the constraints in force](../01-intake/01-constraints-and-the-design-system.md) skip a service with no current release, each recording on its [last check](../../08-operations/08-drift-detection.md) that no further pass is owed. Every record stays, its retention following [the log's](../../09-gate-policy/03-what-is-not-in-it/02-retention.md) the way every record's does, and the repository and the store are the owner's to remove, as creating them was. A retired service is never revived: software the owner brings back is adopted as [a service that already exists](01-a-service-that-already-exists.md). What it costs is a write refused until every consumer has moved, which on a service with many is a migration per consumer before the owner may say stop, and a deploy record naming no release that every reader of that record reads as such.

A persistent environment other than production ends by an owner's withdrawal at Factory, refused while any deploy record on it marks a target complete for a release: the owner has the deployer remove each service from it first, the same removal performed for that one environment, called from Factory. A [project](../../11-screens/01-work-ops-factory-people.md) is ended at Factory once every service in it is retired, and its production environment ends with it. A target leaves an environment's field the same way: the owner removes the address, refused while any service's deploy record marks that target complete for a release, so the deployer's removal on that one target comes first, and the [window](../../08-operations/02-the-analysis-window.md)'s target set and the drift detector's reading follow the field. What that costs is an order the owner performs by hand, remove and then withdraw, and a target that cannot be deleted from a list while software runs on it.
