# The allowed package graph. cmd/depscheck reads this file and fails the
# build on an import between two packages of this module that the file does
# not allow, so a wrongly wired package is caught by the build and not by a
# reviewer. The compiler already refuses a cycle; this refuses an edge that
# compiles and should not exist.
#
# A line is a package path relative to factory/, optionally followed by "->"
# and the packages it may import. A package with no arrow may import nothing
# inside this module. Only imports of this module are checked: the standard
# library and pgx are ignored, and a package that is not listed is an error,
# so adding one means adding a line here.
#
# A line beginning with "test" allows an edge that appears only in a package's
# test imports. Every record package's database tests are in an external test
# package and open the pool through postgres, which that package cannot import
# itself once postgres applies its DDL — the arrangement decisionlog's line
# has carried since M0 — so each record package has a test line naming
# postgres. decisionlog's also names secretref, and principal for the caller
# the resolver takes, for the demonstration that a resolved secret's value
# reaches no record, which is the one test that needs a secret and a database
# at once. score's names the record packages its tests
# populate and the log its versions and its decisions are rows of. It does not
# name gate: the score version is a row score appends itself, and the payload a
# decision carries is score's own shape, so a test firing a gate to reach either
# would be a test of two packages at once, and gate imports score, so the
# arrangement inverts as well. Its rules are tested without a database at all,
# over outcomes the test assembles and indexes the way a read of the store does,
# which is what keeps a rule about arithmetic testable as arithmetic.
# notifier's and healthmonitor's name postgres
# although neither owns a table: the notifier's page events are rows of the log
# and the health monitor's answers are queries over the graph, so both need a
# database and records to read. Most of driftdetector's tests open its own
# store through its own opener and never postgres, which is the independence
# checked rather than asserted; head_test.go is the one file that also opens
# the factory's own store, through postgres and decisionlog, because the
# second comparison reads the factory's log directly and a test of it needs
# a log to read. cmd/driftdetector's test opens both and asserts the
# factory's row counts are unchanged across a pass. mergequeue's names the
# packages its tests write through, reaching the whole schema through
# postgres.Apply and driving the queue over a fake repository; what a
# re-verification does to a repository and to a candidate environment is the
# command-line interface's own demonstration. consumercontract's
# names artifact, because the one writer of those rows is the store and a test
# that inserted them directly would prove only that the columns accept what it
# wrote. contractcheck's names most of the graph, because what it answers is a
# query over releases, windows, deploys, contracts, consumer contracts, and
# safeguards at once, and it holds fakes for the four seams — a checkout, a
# run, a candidate's store, and a backfill's completion — that a package test
# has no repository, no process, and no deploy target for. It also names
# targetseam, because completing a deploy target the way the deployer would is
# what its fixtures ship a release through. postgres names record for one call
# and no table: the schema history it keeps of itself writes its rows with the
# same timestamp every record in the store is written with.
#
# The edges whose reason the list does not make obvious have it stated here.
#
# artifact -> criterion and artifact -> consumercontract are the two imports between
# record packages that both own tables: the artifact store is the one writer of
# both, so a spec version and the criteria it introduces are written in one
# transaction, and so are a consumer contract version and the predicates it introduces.
# The alternative in each case is two writers of one table.
#
# legalhold -> service is an import for one table name. A hold on a project
# reaches the project's environment and every service in it, so the read of
# whether a hold reaches a service asks which project that service lies in,
# which is a field of the service record. The alternative was the caller passing
# the project, and a caller that passed nothing would lose the reach silently.
#
# service -> secretref is an import for a type. A service's repository credential
# is held by name on the service record, one name on a host that cannot restrict
# by branch and two where it can, and a second spelling of a secret's name here
# would be a string a printer could render beside a value.
#
# consumercontract -> contract is the third and it is an import for a type. A
# predicate is an assertion about one element of a contract, and deciding one
# against a form is what the predicate means — so the vocabulary of a form belongs
# to the package that owns the contract, and a second spelling of an element here
# would be two able to disagree. It is the arrangement gate -> criterion already
# has one level along.
#
# gate imports criterion for one type: what deciding a criterion against a build
# produced, which is what the Merge to master gate reads about the item's own behaviour. The
# vocabulary of an outcome — passed, failed, and undecided read the way a failure
# is — belongs to the package that owns the criterion, so the gate names it rather
# than keeping a second spelling of it.
#
# The gate's other edges are the reads the design puts at the moment of firing
# and at no other, one per thing a firing has to know. artifact is the version
# under decision: its content digest goes on the open event beside its
# identifier, and its author is what the refusal of a close by that author
# compares against. people is who holds the row's duty, read at the firing for
# what the open event says and again at the close for the two refusals that turn
# on whether a second holder exists. halt is the one hold no approve passes, read
# here rather than computed by a caller because the refusal it carries is the
# gate's. environment is whether every target of the production environment
# serves a share, which bounds the strategy to the row without a control where
# one does not; area is the hazard severity that bounds the schedule; service is
# the four fields the deployer populates, without which the production deploy row
# cannot auto-pass. item is the count the attempt limit is compared against and
# the dispatch that writes the escalation onto an item that exceeded it. intent
# is the six states an intent may be in, read before every firing on an item —
# the read itself is a function the composition supplies, and this edge is for
# the vocabulary.
#
# What it does not import is the records the factory's own holds are computed
# from: the deploy records of a dependency's service, the open windows, the error
# budget, the advisories, the freeze. Those reach the gate through the Holds
# interface its caller implements, which is what keeps the fan-out here to what a
# firing itself reads.
#
# gatepolicy is imported by everything that holds an authored value and by
# nothing it imports itself. It owns no table and is the vocabulary of gate
# policy — the parameters, what each value means, and the direction a safeguard on it
# points — which two packages would otherwise each keep a copy of.
#
# score reads the graph, so it imports the record packages the factors are
# computed from: the artifacts an author wrote, the closed decisions in the
# log, the items in an area and the intents they answer, the areas whose hazard
# severity the context group reads, the releases of a service, and the contracts
# it publishes with the consumer contracts naming them. It writes one thing and
# it is not a record: the score version is a row of the decision log, so score
# owns no table and postgres does not name it. What it does not import is a
# repository: the two inputs that are not records are the build's diff and the
# exposure list, both derived per toolchain by the component that built and
# handed to it.
#
# Three of those edges arrive with the learning, and all three are outcomes
# rather than factors: window for the exits and the finest size each window
# reports the traffic reached, deploy for the rollbacks and the releases each
# undid, and incident for the crossing that says a window's size or its power was
# too coarse. What it does not import is boundary: whether a size is reachable at
# all is arithmetic the window does and reports on its record, and a second copy
# of it here would be two able to disagree about the one number whose whole
# purpose is to match what the boundary does.
# What it still does not import is policy — the direction is policy -> score,
# because the value in force is the authored one where there is one and the
# supplied one otherwise, and a score that read the authored value would be
# supplying a value against what an owner wrote.
#
# policy is Factory's writer, so it imports every record an owner authors a
# value on or creates — the environment, the service, the area, the project, the
# factory-wide settings record, the safeguard, the halt and the legal hold — and
# calls the transaction-taking write each of them exposes. It imports decisionlog
# because the policy version is a row of the log rather than a table of its own:
# it appends through the log's writer inside the same transaction as the record
# write, and reads every version back through the log's reader. It imports score
# for the value the score supplies where an owner authored nothing. It imports
# project because the write that creates one writes production's environment in
# the same event, an owner's request naming the project by name alone.
#
# mergequeue imports gate because the shape of a decision's two payloads is
# gate's: the queue's order is the time of the merge approval in the log, and a
# queue that unmarshalled those payloads itself would be a second place naming
# the same JSON fields. It asks gate for the approval times instead. It also
# takes from gate the vocabulary a rejection is written in: the stage the item
# returns to, and the verdict the score learns the rejection as.
#
# Its other edges are the records one pass reads. intent is the state that
# permits an item's membership and the tier its order begins with, read per
# member. halt is the one authored record whose subject is the factory, read
# because records.md names the merge queue one of its two readers. build is the
# two comparisons no criterion reads: the design system constraint record the
# two builds name, and the digests of what each resolved. environment is an
# import for a type — the composition a run was performed against, compared
# between the run that passed and the re-verification, which is what tells the
# second reading of a failure from the third. What it does not import is
# anything that reaches a repository or a deploy target, and it does not import
# item's dispatch either: components.md's row for the queue names no dispatch,
# so the transition an outcome causes is the caller's write.
#
# cmd/factory imports nearly everything, because it is the command-line interface the
# four screens are deferred with — the one place the whole path is composed,
# the one place an owner can author a parameter or place a safeguard, and the
# deployer the merge queue and the health monitor reach a repository, a
# candidate environment, and a rollback through.
#
# cmd/driftdetector imports what one pass reads: the production environment
# record, the services, the current production deploy of each, the releases and
# open windows an excused build is read from, the seam and the local target it
# reads through, and its own store. Everything it touches of the factory's it
# only selects from. build is the recorded artifact digest the first
# comparison reads beside the build id. lastcheck is the third comparison's
# own read, lastcheck.Stale over the factory's pool, to find a factory
# component that stopped. principal is what every operation of the seam now
# takes; the drift detector calls as itself, a component, the same as every
# other caller of a seam that decides nothing on the principal it carries.
#
# Four more edges arrive with everything downstream of a deploy.
#
# window -> boundary is an import for a type. The read a window closed on is a
# boundary.Observed — the counts the exit was decided from — and a second spelling
# of those four counts here would be two able to disagree with the package that
# evaluates them. It is the arrangement consumercontract -> contract already has.
#
# build -> exposure is an import for a type. The exposure list the build runner
# derived is stored on the build record, and the vocabulary of the four kinds
# belongs to the package that derives them; a second spelling here would be two
# able to disagree. It is the arrangement window -> boundary already has. The
# score keeps a spelling of its own, which is the repetition this module pays for
# locality: the score reads no repository and this decides no gate, so a caller
# holding both hands one to the other in one place.
#
# exposure imports nothing inside this module. It is the extractor over a
# checkout — one git diff and the four readings over it — per toolchain, and a
# package with no dependencies is what makes a program analysis testable over a
# temporary repository alone. It is the arrangement contract's own derivation
# has.
#
# boundary imports nothing, inside this module or out of it beyond the standard
# library. It is the analysis window's arithmetic over numbers its caller has
# already read, and a package with no dependencies is what makes the one part of
# this milestone that is a claim about statistics testable as arithmetic alone.
#
# healthmonitor is the health monitor and imports what it writes and what it reads
# the graph through: the window and the incident it writes, the intake it raises a
# revert intent through, the notifier it pages on a failed exit that rolled
# nothing back, the policy for the window's parameters, and release, item, and
# deploy for the records a rollback's target and a settled incident are computed
# from. gatepolicy is the vocabulary the size and the power are keyed by, one per
# quantity. lastcheck is its own last check per service, a writer among the
# seven records.md names, and decisionlog is for [decisionlog.Row], the shape the
# notifier's own delivery reads back. people is the one duty a page of this
# component names — an open incident with no open window reaches whoever holds
# (2) — and nothing else here reads that declaration. service is the four fields the deployer
# populates, without which a window opens recording only that it measures
# nothing, and the objective an explicit threshold is read against. boundary is
# the one import that is arithmetic rather than a record: the window's size and
# confidence resolve to a boundary. What it does not import is a repository or a
# deploy target — a rollback is behind an interface its caller implements, and so
# is the quantity it reads and the control it starts and tears down. That is the
# arrangement mergequeue already has.
#
# people imports policy because a write to the holding table — a duty held,
# an obligation named — appends a policy version with People as caller before
# the table itself changes, through policy.Factory.AppendPeopleVersion, which
# policy already exposes for this direction. Policy does not import people
# back: the declaration policy's version carries is supplied to it by the
# composition, never read from this package, which is why the edge runs one
# way. It imports legalhold for the half of a mapping's deletion this package
# can decide on its own: a hold on the whole install reaches every mapping
# there is, where a hold on one service or one project reaches one only
# through the records that key is written on, which is the erasure list's walk
# and is the caller's check.
#
# notifier imports people because routing is a read of that declaration, and
# decisionlog because a page event is a row of the log. It imports lastcheck
# to write the notifier's own record beside the health monitor's and the
# deployer's, and driftdetector because the notifier is the one reader of the
# detector's store: the detector calls nothing, so the notifier reads it
# itself, widens and answers the one wait that has no other caller, and
# catches up the detector's own delivery at the factory's next start. It
# imports nothing that creates a wait its caller does not hand it, and
# factorysettings for the harm-marked report page's cap and off switch.
# service is the paging hours a wait of the second kind is deferred against.
#
# driftdetector imports decisionlog for decisionlog.Row and
# decisionlog.Row.ChainHash alone, to recompute the log's chain forward from
# the head it recorded: it selects decision_log directly with a query of its
# own rather than through decisionlog.Reader, which would append a read event
# this package has no fencing token to write. It imports lastcheck for
# lastcheck.Stale, an ordinary read over the factory's pool, to find a
# factory component that stopped. Both reach the factory's store read-only
# and never through postgres, which would make it a store the factory
# applies and no longer independent of it.
#
# Three more edges arrive with contracts.
#
# contract imports record and nothing else. It is written by the merge queue
# inside the mint's transaction, so what it takes is a pgx.Tx rather than a pool,
# and the form and the diff beside its records are arithmetic over text — which is
# what makes the one part of this milestone that is a program analysis testable
# without a database.
#
# contractcheck is enforcement and imports what it reads the graph through: the
# contract and the consumer contract it decides between, the deploy record that says what
# is running, the environment for the addresses production's current release is read
# against, the release and window records a service's last known-good release
# is computed from, boundary for the counts a window closed on and gatepolicy for
# the predicate kind vocabulary those counts and the store rule are read against,
# the policy for the list of allowed predicate kinds and the safeguards' predicates,
# the service for the name a removal statement is written with, item and intent for
# the walk from a release back to the intent whose evidence a brownout is keyed by
# and the removal it raises through, and gate for the vocabulary of which
# mechanical check rejected. What it does not import is a repository or a deploy
# target — a form and a consumer contract are derived behind an interface its caller
# implements, and so is the run it observes and the store state and the backfill's
# completion it reads. That is the arrangement healthmonitor already has.
#
# driftdetector's store is not the factory's — no factory component may write
# it — so it brings its own opener and its own applier rather than reaching for
# package postgres, and postgres does not name it. What it shares with the
# factory is the column conventions, which are about who wrote a row and not
# about which store it is in. Its three edges — record, decisionlog for the
# second comparison and lastcheck for the third — are the paragraph above.
#
# Every package that writes to the factory's own store imports lease, to call
# Fence inside its own write transaction before the write it guards —
# ../../end-goal/one-process.md is what that guards against. The edge is added
# to each package's line as it is wired to call it, so a package's line naming
# lease and one not yet naming it may sit side by side for a time.
