# The allowed package graph. cmd/depscheck reads this file and fails the
# build on an import between two packages of this module that the file does
# not allow, so a wrongly wired package is caught by the build and not by a
# reviewer. The compiler already refuses a cycle; this refuses an edge that
# compiles and should not exist.
#
# A line is a package path relative to factory/, optionally followed by "->"
# and the packages it may import. A package with no arrow may import nothing
# inside this module. Only imports of this module are checked: the standard
# library and pgx are ignored, and a package that is not listed is an error,
# so adding one means adding a line here.
#
# A line beginning with "test" allows an edge that appears only in a package's
# test imports. Every record package's database tests are in an external test
# package and open the pool through postgres, which that package cannot import
# itself once postgres applies its DDL — the arrangement decisionlog's line
# has carried since M0 — so each record package has a test line naming
# postgres. decisionlog's also names secretref for the demonstration that a
# resolved secret's value reaches no record, which is the one test that needs
# a secret and a database at once. score's names criterion, gate, policy, and
# the record packages its tests populate: the outcomes it counts are the
# decisions a gate wrote and the windows the health monitor closed, so its tests
# fire real gates rather than writing those rows by hand — a test that wrote
# them would prove only that the score can read what the test writes — and a
# gate is fired with a policy. Its rules are also tested without a database at
# all, over outcomes the test assembles and indexes the way a read of the store
# does, which is what keeps a rule about arithmetic testable as arithmetic.
# notifier's and healthmonitor's name postgres
# although neither owns a table: the notifier's page events are rows of the log
# and the health monitor's answers are queries over the graph, so both need a
# database and records to read. driftdetector's tests open its own store
# through its own opener and never postgres, which is the independence checked
# rather than asserted; cmd/driftdetector's test opens both and asserts the
# factory's row counts are unchanged across a pass. mergequeue's names the
# packages its tests write through, reaching the whole schema through
# postgres.Apply and driving the queue over a fake repository; what a
# re-verification does to a repository and to a candidate environment is the
# crude interface's own demonstration. consumercontract's
# names artifact, because the one writer of those rows is the store and a test
# that inserted them directly would prove only that the columns accept what it
# wrote. contractcheck's names most of the graph, because what it answers is a
# query over releases, windows, deploys, contracts, consumer contracts, and
# safeguards at once, and it holds fakes for the two seams — a checkout and a
# run — that a package test has no repository and no process for.
#
# The edges whose reason the list does not make obvious have it stated here.
#
# artifact -> criterion and artifact -> consumercontract are the two imports between
# record packages that both own tables: the artifact store is the one writer of
# both, so a spec version and the criteria it introduces are written in one
# transaction, and so are a consumer contract version and the predicates it introduces.
# The alternative in each case is two writers of one table.
#
# consumercontract -> contract is the third and it is an import for a type. A
# predicate is an assertion about one element of a contract, and deciding one
# against a form is what the predicate means — so the vocabulary of a form belongs
# to the package that owns the contract, and a second spelling of an element here
# would be two able to disagree. It is the arrangement gate -> criterion already
# has one level along.
#
# gate imports criterion for one type: what deciding a criterion against a build
# produced, which is what the Merge to master gate reads about the item's own behaviour. The
# vocabulary of an outcome — passed, failed, and undecided read the way a failure
# is — belongs to the package that owns the criterion, so the gate names it rather
# than keeping a second spelling of it.
#
# gatepolicy is imported by everything that holds an authored value and by
# nothing it imports itself. It owns no table and is the vocabulary of gate
# policy — the parameters, what each value means, and the direction a safeguard on it
# points — which two packages would otherwise each keep a copy of.
#
# score reads the graph, so it imports the record packages the factors are
# computed from: the artifacts an author wrote, the closed decisions in the
# log, the items in an area, the releases of a service, and the contracts it
# publishes with the consumer contracts naming them. It writes only its
# own version record. What it does not import is a repository: the one input
# that is not a record is the build's diff, measured by the component that
# built and handed to it.
#
# Four of those edges arrive with the learning. Three are outcomes rather than
# factors: window for the exits and the read each window closed on, deploy for the
# rollbacks and what each swept, and incident for the crossing that says a window's
# size was too coarse. The fourth is boundary, and it is an import for arithmetic:
# whether a size the score is asking for is reachable at all is the units that size
# needs against the traffic a service receives, and the units it needs are what the
# health monitor already reads the window against. A second copy of that arithmetic
# here would be two able to disagree about the one number whose whole purpose is to
# match what the boundary does.
# What it still does not import is policy — the direction is policy -> score,
# because the value in force is the authored one where there is one and the
# supplied one otherwise, and a score that read the authored value would be
# supplying a value against what an owner wrote.
#
# policy is Factory's writer, so it imports every record an owner authors a
# value on — the environment, the service, the area, the factory-wide settings record,
# and the safeguard — and calls the transaction-taking write each of them exposes,
# appending the policy version inside the same transaction. It imports score
# for the value the score supplies where an owner authored nothing.
#
# mergequeue imports gate because the shape of a decision's two payloads is
# gate's: the queue's order is the time of the merge approval in the log, and a
# queue that unmarshalled those payloads itself would be a second place naming
# the same JSON fields. It asks gate for the approval times instead. What it does
# not import is anything that reaches a repository or a deploy target — that is
# behind an interface its caller implements.
#
# cmd/factory imports nearly everything, because it is the crude interface the
# four screens are deferred with — the one place the whole path is composed,
# the one place an owner can author a parameter or place a safeguard, and the
# deploy agent the merge queue and the health monitor reach a repository, a
# candidate environment, and a rollback through.
#
# cmd/driftdetector imports what one pass reads: the production environment
# record, the services, the current production deploy of each, the releases and
# open windows an excused build is read from, the seam and the local target it
# reads through, and its own store. Everything it touches of the factory's it
# only selects from.
#
# Four more edges arrive with everything downstream of a deploy.
#
# window -> boundary is an import for a type. The read a window closed on is a
# boundary.Observed — the counts the exit was decided from — and a second spelling
# of those four counts here would be two able to disagree with the package that
# evaluates them. It is the arrangement consumercontract -> contract already has.
#
# boundary imports nothing, inside this module or out of it beyond the standard
# library. It is the analysis window's arithmetic over numbers its caller has
# already read, and a package with no dependencies is what makes the one part of
# this milestone that is a claim about statistics testable as arithmetic alone.
#
# healthmonitor is the health monitor and imports what it writes and what it reads
# the graph through: the window and the incident it writes, the intake it raises a
# revert intent through, the notifier it reports a rollback on, the policy for the
# window's four parameters, and release, item, and deploy for the records a
# rollback's target and a settled incident are computed from. boundary is the one
# import that is arithmetic rather than a record: the window's size and confidence
# resolve to a boundary. What it does not import is a repository or a deploy
# target — a rollback is behind an interface its caller implements, and so is the
# quantity it reads. That is the arrangement mergequeue already has.
#
# notifier imports people because routing is a read of that declaration, and
# decisionlog because a page event is a row of the log. It imports nothing that
# creates a wait: its callers hand it one, so the component that delivers
# everything waiting on a human depends on none of the things that wait.
#
# Three more edges arrive with contracts.
#
# contract imports record and nothing else. It is written by the merge queue
# inside the mint's transaction, so what it takes is a pgx.Tx rather than a pool,
# and the form and the diff beside its records are arithmetic over text — which is
# what makes the one part of this milestone that is a program analysis testable
# without a database.
#
# contractcheck is enforcement and imports what it reads the graph through: the
# contract and the consumer contract it decides between, the deploy record that says what
# is running, the release and window records a service's last known-good release
# is computed from, the policy for the list of allowed predicate kinds and the
# safeguards' predicates, the service for the name a removal statement is written with, the
# intent it raises a removal through, and gate for the vocabulary of which
# mechanical check rejected. What it does not import is a repository or a deploy
# target — a form and a consumer contract are derived behind an interface its caller
# implements, and so is the run it observes. That is the arrangement healthmonitor
# already has.
#
# driftdetector imports record and nothing else. Its store is not the factory's — no
# factory component may write it — so it brings its own opener and its own
# applier rather than reaching for package postgres, and postgres does not name
# it. What it shares with the factory is the column conventions, which are about
# who wrote a row and not about which store it is in.
#
# Every package that writes to the factory's own store imports lease, to call
# Fence inside its own write transaction before the write it guards —
# ../../end-goal/one-process.md is what that guards against. The edge is added
# to each package's line as it is wired to call it, so a package's line naming
# lease and one not yet naming it may sit side by side for a time.
