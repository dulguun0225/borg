# factory

The factory's code. What it is for and what it is built toward are in [`../end-goal/`](../end-goal/README.md); the order it is built in is [`../roadmap.md`](../roadmap.md); the rules it is written under are the _Code_ section of [`../CLAUDE.md`](../CLAUDE.md#code). This file is the map those rules require to ship with the code: every package, what it owns, where the edges between them are stated, and how to run it.

## The packages

| Package | What it owns |
|---|---|
| [`record`](record) | The graph's conventions: the actor — one of three kinds, `human`, `component` or `agent`, an opaque key that is never a name, and, on every one of the three, whether that key is claimed or verified — identifier generation, the timestamp format, and the SQL text every record table composes for its columns, their constraints, and the format version each row carries. It owns no table. |
| [`decisionlog`](decisionlog) | The chained log: one table of ten shapes, and one writer with a method per shape and part. A decision is up to four rows — an open event appended when a gate fires, a close event naming it and carrying the verdict, an abandonment where no verdict is coming, and an acknowledgement per human — a wait is two, and the other eight shapes are one row each; `Truncate` is the one method that deletes, refused wherever a legal hold stands. Reading goes through a `Reader`, which holds the same fencing token a writer does and appends a read event naming the principal — its actor in the row's own columns, an agent's dispatch and scope in the payload — before every answer, `Verify` walking the chain and naming the first row that breaks it. |
| [`lease`](lease) | The store's account of itself: the one row that makes exactly one instance of the factory run at a time — who holds it, when the hold lapses, and the number that rises at every acquisition — the acquisition that takes it where it is unheld or expired and fails where anything holds it, the release a process stopping cleanly makes, and the fencing token every write elsewhere in the store is checked against inside its own transaction. It is not a record of the graph and carries no actor. |
| [`erasurelist`](erasurelist) | The erasure list: an append-only file on the host, outside the recovery unit, one JSON line per row with the payload format version first, the key a step is taken under, the instant, the kind of record reached, and what was removed — never the words. `Append` writes nothing where the key already appears; `ReadKind` is a read by kind, which is how a store replays the rows naming its own records after a restore; `Retire` removes a row once the erasure it records is older than the retention its caller supplies. It owns no table and carries no actor, a file and not a row of the store. |
| [`principal`](principal) | Who a call is made as: a human's actor, a component's, or an agent's plus the dispatch that put it on an item and the scope it was dispatched under. It decides nothing and is recorded by whatever the call reaches. |
| [`secretref`](secretref) | The reference type every other package uses in place of a secret, and the one resolver that reads a value, recording the principal that asked for it beside the name. A `Ref` has one field and it is the name, so nothing that renders one can render a value. |
| [`targetseam`](targetseam) | The named operations the deployer reaches a deploy target through — `Deploy`, `Stop`, `ReadRunning`, `ShiftTraffic`, `SetInstanceCount`, `ApplySchemaChange`, `Snapshot` — as an interface, every operation taking the principal making the call. `Deploy` and `Stop` each report how the instances they ended were replaced, a drain or a cut, which is what the deploy record's row per target names. A schema change carries the release that ships it and, at an adopted service's first release, the mark that says the store arrived carrying it; a history row carries both back. `Fake` records what was called on it and reaches nothing; `localtarget` is the implementation the demonstrations deploy against. No agent reaches a deploy target at all. |
| [`postgres`](postgres) | Opening the pool, applying package `lease`'s table alone — the one thing created before the lease is acquired — and applying each package's DDL from one ordered list written in the source. No ORM, no migration framework. Beside it, the store's schema history — one row per change, naming the version that shipped it, its identity, a checksum of its text, and whether it widened the store or removed something — and the start that reads it and refuses to start against a store this version cannot read. |
| [`cmd/depscheck`](cmd/depscheck) | Failing the build on an import between two packages of this module that [`deps.txt`](deps.txt) does not allow. |
| [`cmd/tracecheck`](cmd/tracecheck) | Failing the build where the code and the design do not hold to each other: a claim in `../end-goal/claims.txt` whose sentence is not found exactly once in its file, a `doc.go` outside `cmd/` or a screen `README.md` citing no claim or citing one the inventory lacks — a command's `doc.go` is held instead to carrying at least one reference — a built claim nothing cites, an unbuilt or stated claim something cites, a design file under `how-the-factory-works/` or `what-the-factory-does/`, other than a README, that no claim names, a reference into a Markdown file that points at nothing, and a package named for no phrase the design uses. |
| [`intent`](intent) | The intent — its source, its statement, its six-state refinement state, its two attempt counts, its tier, project, evidence, deadline and constraint — the question attached to it, the interview's rounds and the acceptance round that follows production among them, and the requirement recording what the factory understood is wanted, `Intake` being the one writer of all three. |
| [`constraint`](constraint) | The constraint record of the document kind: what an owner supplies that binds every item inside its reach — the factory, one project, one area, or one intent — from arrival until an owner withdraws it, and the replacement that corrects one, never an edit. `Writer` is intake's, called from Factory for a permanent one and from Work for one whose reach is an intent. The pass over the constraints in force, the design system a build names, and the other five kinds are M12's. |
| [`project`](project) | The project record: an owner's widest grouping of work, and the root every area chain ends at. One writer, an owner at Factory: it is created with production's environment and ended with it, once every service in it is retired, and the row is never deleted. |
| [`service`](service) | The service record: its identity — name, repository, and project — written at decomposition; provisioned, retired, the targets it runs on, the window's size and power per quantity, its confidence, cap, window limit and exposure bound, the bake volume between one target of a rollout and the next, the backlog cap on how many releases wait behind a rollback hold, the environment-hour and instance-hour rates a span is converted at, the operation cap and the overflow operation the excess lands in, the explicit threshold per quantity a safeguard sets with the size beside it, the search budget, the mutant cap, the failure-record key cap, the unreliable bound, the incident-raised item bound, the objective and paging hours, the mutation floor, the fraction of its instances a release keeps, the maximum concurrent kept fleets, the size and average run length of the reading against its own recent history, the proof test rate, the periods of a change freeze, the product licence and the snapshot retention, each authored by an owner at Factory; and the deployer's four reachability fields written at adoption and at every first release. Three writers, and the seam between them is the field. |
| [`item`](item) | The item — its intent, service, area, branch, what it waits on, and the requirements it answers — written once by decomposition's `Create`, which also `Supersede`s an item at its replacements and `Repoint`s what a standing item waits on, both refusing an edge that would close a cycle over what waits on what. `Dispatch` writes the stage, the attempt count, and the priority after: `Advance` one stage forward with an attempt counted on entry, `ReturnTo` a stage with nothing counted until it is entered again, `Escalate` and `ClearEscalation` for the attempt limit, `Drop`, `SetPriority`, and `End`. What a stage spent is `agentrun`'s and no field here. |
| [`agentrun`](agentrun) | The agent run record: one per run of any agent, written once by the component that performed it — what ran, what it ran on (an item and its stage, or an intent), what it served the run on (the credential and the processing location the fleet entry named, and the lender's per-person key and account kind read off the People declaration at the run), and what it spent (units per kind, the time they were returned, the sources handed over, and the amount converted at the owner's rates, absent where a kind has no rate). Reads: by item, by intent, by model version, and the sum by credential since a period start that a spend ceiling compares against. |
| [`inputmanifest`](inputmanifest) | The input manifest: what context assembly hands an agent before a run, named by reference — the item or intent and its stage, the material handed over, the read-at-once bound applied, the selection rule version, and what was withheld or truncated and why. Written once per dispatch; context assembly is not built, so the caller that dispatches writes it for now. |
| [`artifact`](artifact) | The artifact store: an artifact's version chain — an item's, a role's, a subject's, or the one selection rule's — its content digest, its authorship and author, and the calls in which a version and the records it introduces are submitted together: a spec version with its criteria, its withdrawals and its screen state machines, and a consumer contract version with its predicates. Also the input manifest a version was authored from, the one entry an authorship does not name — the shipped version the factory enters itself, naming which of the two events entered it, the install's alone standing in force ungated — and `Redact`, the one exception to insert-and-never-update. |
| [`criterion`](criterion) | A criterion of a service: its stable id, its pattern, its provenance queries, the query for which criteria are in force for one build — a build being a set of items — the encoding checks that tie a criterion to the test code deciding it, the Spec gate's rejection of a build in an irreversible area no criterion in force bounds, what deciding one against a build produced, undecided among the three outcomes, the mutation score read over a run's encodings with its coverage and its could-not-derive, and the outcome history a bound reads as unreliable. |
| [`screenstatemachine`](screenstatemachine) | A screen's state machine: its states, events and transitions, the chain of supersessions that is the screen's identity, the well-formedness checks a closed machine must pass, the check that a transition leaving the screen names one still in force, the transition check derived from a build with its Go extractor, and the drivers that put a screen in each declared state. |
| [`dispatch`](dispatch) | The dispatch component: the match of an item's stage against a role and of its service and area chain against a scope, or of an intent against one of the two roles put on an intent, and what runs an agent. One dispatch reads the intent's state, matches the role and the scope against the fleet entries in force and the role prompt version in force, computes the conditions those records make readable, writes the transition onto the item, writes the input manifest with the classes of material the entry does not name withheld and recorded as excluded, runs the role under a principal naming the model version and the dispatch, asking the provider for the effort the entry names, records one agent run per call — the processing location off the entry and the lender, the account kind and the rates off the People declaration among its fields — and compares the item's own count for the stage against the attempt limit, escalating over it and telling the notifier that it did. It also orders admission where more is ready than the infrastructure admits, by the intent's tier and then the item's priority. Five of the six conditions that stop a dispatch are computed here and each is a hold row in the log, one per item and stage, re-matched and closed when its condition is gone: a stage no entry covers, a role with no prompt version in force, a credential a run could not reach, a credential whose spend since the period's start reached the ceiling `people` holds — or whose runs a rate does not cover, which fails closed — and a document-kind constraint requiring seam 5 where the factory does not enforce it. Beside them it writes the two rows a credential itself stands as, and `ClearCeiling` is the owner authorising an overage for one period. It owns no table: the item's stage is `item`'s, the manifest `inputmanifest`'s, the run record `agentrun`'s, the entry `fleetentry`'s and read-only here, and the hold the log's. |
| [`gate`](gate) | The gate component: firing the eight rows of the default path, a row per further deploy environment, and the five that belong to no item; reading the intent's state, the rows already pending, the version under decision, the holds standing and who holds the row's duty before it appends anything; and opening and closing a decision through `decisionlog`. A decision is two rows and may carry two more — an acknowledgement, and an abandonment where no verdict is coming. The verdict is a human's where a mark put one at the row and the factory's own otherwise, and the factory has two: it may not approve over a human, and it rejects before one is asked, because a mechanical check rejects on its own terms before anyone gives a verdict. Refer is the fourth verdict and the one that closes a row and re-fires it. It owns the vocabulary of the fourteen holds, of the checks that reject mechanically, of the marks that say what put a human at a row, and of the rollout strategy, which the score picks at the production deploy row and this package stores on the open event and validates, plus the read of when each item's merge approval closed. |
| [`build`](build) | A build record, one per commit built, naming the service and, where there is one, the item it was built for, the commit, the artifact digest, the resolved set of third-party packages with its per-ecosystem coverage, the notice file, the design system constraint in force, the shipped-bundle identity — which release of the product built it — the exposure list the build runner derived from its own checkout and whether that checkout declares a schema change, and what the build's own process decided about the criteria whose encodings declare it. |
| [`exposure`](exposure) | The exposure factor's extractor, per toolchain and Go being the one built: what the change reaches that the service did not reach before, read out of the diff between the base and the candidate's commit and out of the build's resolved set — an outbound call added, a credential named or read either way, an authorization check removed or weakened, and a dependency change, which is this build's resolved set diffed against the set of the service's current release's build. Each entry names the file and the line, or the resolved set where nothing in the manifest changed. It owns no table, reaches no database, and imports nothing inside this module; a diff it could not take is unavailable with the reason, which resolves the factor rather than reading it as nothing. |
| [`securitypredicate`](securitypredicate) | The factory's own list of security predicates — the second of the two lists a predicate is drawn from, shipped as content of the product rather than authored, one per toolchain and Go being the one built, each naming the factory version that shipped it — and the derivations that decide its kinds against a build's checkout. The Go list ships no kind: what a security predicate asserts is not in the design, so the content is what is missing. A toolchain with no list, a checkout no derivation can read, and a kind no derivation covers are one outcome, could not derive, which puts a human at the Merge to master row; a kind that does not hold is that row's rejection. It owns no table, reaches no database, and imports nothing inside this module. |
| [`release`](release) | The release record and the number, minted per service in master's order at one of two occasions — the fast-forward, naming the item, and a commit accepted onto master by another path, naming a build and no item — and the mint that runs the queue's contract publication inside its own transaction. Nothing here names a contract version: the version names the release and copies its number, so a release names what it publishes as an inbound edge. The authorship rollup is a query over the artifact store's own versions. |
| [`deploy`](deploy) | The deploy record, its completion per target, and the mitigation, and the rollout that performs them, reaching a target through `targetseam`: the ordered walk with a bake between targets on either strategy, the strategy performed written once something was, the schema changes and the snapshot applied before traffic moves — none of them at an adopted service's first release, which writes them into the store's history as found applied — the slow rollback that applies no schema change, verifies the artifact's digest before redeploying and advances what it undoes target by target, the restart that resumes an unfinished deploy, the mitigation the deployer performs on a human's instruction from Ops, of which there are two, and the removal a retirement calls for, which ends every instance of a service on every target of a persistent environment and writes a record per environment naming no release. Each target row dates three fleets — the release's own, the control's, and the instances kept for the release a rollback would return to — and carries their instance-hours and what they converted to. The environment it names is an environment record's id, and what it names as deployed is the build it put there and, where it is deploying one, the release. Each record also carries the configuration digest, over the resolved value set of the service's configuration at that deploy, and the way-in token digest, of the token the deployer minted for the way in and never the token. |
| [`agent`](agent) | The roles an agent is put on — `Interviewer`, which runs on an intent, and the four authoring roles `SpecAuthor`, `Planner`, `TaskAuthor`, `Implementer` — the `Model` interface all five call, its two implementations — `OpenRouter` and `Anthropic` — each reaching a credential of its own through `secretref` and each returning the units the provider counted per kind, and `Paced`, which wraps a model so two calls never start closer together than an interval. A role works from the role prompt version handed to it and refuses to run with none; the words the product ships are constants here, one per role including the decomposer, which no type here runs, and what the factory enters at its first start. |
| [`localtarget`](localtarget) | A `targetseam.Target` that runs the software as a local process, one per service, in one directory — the implementation the demonstrations deploy against. An environment with several targets is several `Local`s, reached in order, because an address on this platform is a directory. It moves a process rather than traffic, so it serves no share and reports so: the deployer records the row it performed as one without a control where a target declared as serving one refuses the shift. `Stop` ends the process outright and reports the cut that is. `ApplySchemaChange` runs the service's own script — or, for a change found applied, writes the history row and runs nothing — and `Snapshot` copies and verifies the store's directory; the history's line names the release that shipped each change. |
| [`gatepolicy`](gatepolicy) | The vocabulary of everything an owner authors: the thirteen parameters of gate policy's eleven rows, what each value means, the record its scope names, the key its value is held under there, and the direction a safeguard on it points; the retention values and rates authored and not among the eleven, the strategy default on production's environment record, and the twelve the design names on the service record; the two parameters only a safeguard sets and nothing authors; the nine kinds of predicate a consumer contract may draw from, which are the allowed kinds' unauthored value; and the quantities the health monitor reads. It owns no table, the way `record` owns none. |
| [`score`](score) | The risk score and the loop that moves it: the score version — a row of the decision log, naming the published formula, the weights each factor set gives each factor, the published rules by which a supplied value moves, every value the score supplies per subject, the bands of the number, the drift readings and the false alarms per human — the factors of the design's four groups over three factor sets, the assessment a gate fires with — computed under the version in force at that gate's scope — the resolutions that put a human at a row whatever the number reads, the rollout strategy the production deploy takes and the bound the version names it against, the pass that reads every outcome in the store, the recalibration that refits the weights, and the held-out sample, which is the one thing in the factory that takes a human off a gate row. It owns no table. |
| [`policy`](policy) | Factory's writer: the one component every authored value, every safeguard, every halt and every legal hold goes through; the policy version it appends in the same transaction, a row of the decision log naming the write, the whole authored state and the People declaration in force, and no table of this package's; the re-derivation the factory's start makes of every authored field the newest version names; the value in force as a read of three things, authored, supplied, clamped by every safeguard reaching the subject; and which score version decides a gate an authored threshold binds, which is the last one confirmed at that scope and not always the newest. |
| [`safeguard`](safeguard) | The safeguard record — its subject, drawn from the nine kinds the design names, the parameter it binds, its direction, its bound in whichever of three shapes that parameter takes, and its routing — and its withdrawal, a second record naming it and pending until an approved. A contract element is among the subjects, which is what makes a safeguard's predicate storable and is the reason a safeguard is a record rather than a field. |
| [`area`](area) | The area record: an owner's grouping, the area or the project it lies inside — a chain that ends at a project and nowhere else — the hazard severity declared on it, and the item-size target authored on it. `SeverityInForce` is the highest grade named anywhere on the chain, so declaring a finer area never lowers it. |
| [`environment`](environment) | The environment record — production, a customer's, and a candidate's — its ordered targets, its credential reference, the platform a persistent kind is composed on and the concurrent-candidate ceiling and the strategy default authored on production's, the gate thresholds authored on it per row, and, for a candidate's, the item it belongs to and what it was composed from. The compose-and-reclaim cycle is a row of its own, one per composition, closed by a reclamation or by one of the three teardown-for-good events, and what it converts to in environment-hours where a rate was in force. Two writers, and the kind is the seam: an owner creates, withdraws, and changes the targets of the two persistent kinds; the deployer composes, recomposes, reclaims, and tears down a candidate's. |
| [`factorysettings`](factorysettings) | The factory-wide settings record: the attempt limit per stage plus the interview's rounds and decomposition's re-decompositions, the list of allowed predicate kinds, the review sample rate per duty, the held-out sample rate, the advisory severity, the threshold the role-prompt-or-skill gate row reads, retention and its floor, the report channel's two rates, the remediation period per advisory severity, the harm mark's page cap and whether it pages at all, and whether seam 5 is enforced. Beside the record it owns the shortening: a shorter decision-log retention value written pending and named by the gate row that decides it, taking the pending-until-approved shape a safeguard's withdrawal has. |
| [`halt`](halt) | The halt record — the one authored record whose subject is the factory — and its withdrawal, a second record naming it and pending until an approved withdrawal ends it. |
| [`legalhold`](legalhold) | The legal hold record — a subject (a service, a project, or the whole factory) and a reason — and its withdrawal, taking the same pending-until-approved shape a safeguard's does. |
| [`mergequeue`](mergequeue) | The merge queue: its membership as the items whose stage says Merge to master approved them, whose fast-forward has not happened and whose intent's state permits it, its order as the tier, then the priority, then the approval's time in the log, the reading of master against the service's release records at every start and before every mint, the speculation each candidate re-verifies under, the fast-forward and the release it mints with it, the contract versions that release publishes written in the same transaction, the three readings of a candidate that failed its own re-verification, and the four conditions that stop a fast-forward — a halt, the backlog cap, the intent's state, and either reading of master — each a wait it opens and closes in the log. It owns no table and writes no item: what it does to a repository and to a candidate environment is behind an interface its caller implements, and so are the four readings the factory has no writer for yet — the health monitor's store, the design system constraint records, what waits behind a rollback hold, and which item is a revert, which is one of the two exceptions a halt takes. |
| [`boundary`](boundary) | The analysis window's boundary: the two one-sided tests a size, a confidence and a power resolve to over the interval as the unit its variance is estimated over, each valid at every point it is read, and the reading that says `passed`, `failed`, or neither. It owns no table, reaches no database, and imports nothing — which is what makes the one part of the factory that is a claim about statistics testable as arithmetic alone. |
| [`window`](window) | The analysis window record — one per production deploy of a release its service has not watched before, or over a build the search calls for, naming no release — its four exits and the one close that writes exactly one of them, whether `passed` was available to it and whether the release was held out, the size and power per quantity, confidence, cap, boundary version and two versions resolved at the open, the target set the boundary was allocated over, the emission version each arm was read at, the read it closed on so that an exit can be recomputed from the numbers it was decided on, how many windows a service holds open, the closed windows a rollback's target is computed from at every boundary version, every closed window at the boundary version in force, which is what the score learns from, and the mark a named human at Ops writes against a rollback not caused by the release. |
| [`incident`](incident) | The incident record on a production environment: which of the three readings crossed, the quantity, the boundary it was read against, the failure records copied at the crossing, the release and the deploy it crossed against, its status, and the open incident on one service and one release that makes a further crossing an observation rather than a second intent. Its writer refuses a human, the health monitor being the only thing that writes one. |
| [`people`](people) | The People declaration: which of the owner's twelve duties, held by per-person key, and the named obligation outside the twelve. Beside them, the credentials a key lent — one row per credential name, with whether the account is a person's own or an organisation's, the spend ceiling authored on it in a currency over a period the read derives from a length and a start date in its own time zone, and a rate per kind of unit, model version and effort. A key-to-name mapping — a key and a name and nothing else, the hours a service pages within being a field of the service record — is kept outside the chain so an erasure can delete it alone, refused where a hold reaches the whole install, which this package reads itself, or where the caller's own check finds one over a record the key is written on. Every other write appends a policy version with People as caller, through `policy.Factory`, before the table itself changes; `Rederive` catches the table up from the newest version at the factory's start. Read by the notifier's routing and by every screen resolving a name. |
| [`fleetentry`](fleetentry) | The fleet entry record: a model at an effort in a role with a scope, the credential it runs on, the processing location that credential resolves to, the classes of material it may be handed, how much the model reads at once, and how many dispatches pass between evaluation-set runs. One writer, an owner at Factory, and no component in the pipeline writes back to it. |
| [`notifier`](notifier) | The one notifier: three channels routed the same way on the People declaration by per-person key, a delivery record per row, channel and holder — written on mail and chat too, and on a refused send, which does not stop the channels after it — the four page events appended through the log (reached, acknowledged, widened once to the owner, answered), and the condition that qualifies a wait for a page rather than for mail, including which of the two kinds a wait is, the paging hours a service authors and the pass that delivers a page they held back once they come round, and the harm mark's off switch and the cap past which one page per interval goes out naming the service. It writes its own last check, and it is the one reader of the drift detector's store: the notifier pages, widens and answers a mismatch on its behalf, and catches up the page event for the detector's own delivery at the factory's next start. What delivers a channel is an interface its caller implements. |
| [`contract`](contract) | The contract record — one published interface or store of one service, its kind single-valued across versions — the version record beside it with the release's own number copied on, and the elements of each version with the deprecation mark on each. Beside the records, the vocabulary of a form — each element's kind, the position it is read or written in, whether it is required, its domain and range, and the store's not-null and uniqueness constraints — the diff between two of them with the breaking elements already computed from the position and the kind, and the derivation of a form out of a checkout. The merge queue is the writer and there is no other. |
| [`consumercontract`](consumercontract) | The predicate a consumer's build declares about one element of one contract, on both sides — five kinds over what it receives and four over what it sends — the record, what deciding one against a form and against one observed exchange means, the derivation record beside it naming the extractor, what that extractor could not follow, and why one could not run at all, and the derivation of a consumer's predicates out of its checkout, pairing each mirror with the entry of `consumes.txt` that says which producer its address reaches. Also which toolchains this factory version has an extractor for, published as a fact of that version. One writer, and it is the artifact store. |
| [`contractcheck`](contractcheck) | Enforcement: the producer's own diff against the version its current release publishes, every consumer contract in force decided against the candidate's run, a consumer contract decided against the producer's newest form, the consumer contracts in force from a service's last known-good release to its newest release, the store rule over a migration's middle items and over a backfill, the deprecation list, the detector that raises the brownout intent and the removal intent, whether a release is a brownout, and what a candidate's environment is composed from. It owns no table and writes two records and only two beyond its own last check. What it derives from a checkout, what it observes of a run, and what the candidate environment's own store holds are behind interfaces its caller implements; which backfills a deploy record marks complete is a read of the deploy record and no interface. |
| [`screens`](screens) | The server side of the four screens: every address a human can be on — an item, a decision, a service on an environment, a constraint — as the view the client fetches for it, every write as the call the client makes, the refusal of a call whose factory version is not its own, one server-sent-events stream per address, and the principal every call carries. It owns no table, and every record it reads and every writer it reaches is behind an interface its caller implements, the arrangement `healthmonitor` and `contractcheck` already have. |
| [`clientdist`](clientdist) | The directory the Angular client's build output embeds from: `browser/`, embedded with the standard library's `embed` so one binary carries exactly the client built beside it, and empty but for `.gitkeep` on a clone that has not run the client's build. |
| [`client/`](client) | The four screens as the client itself: an Angular workspace, not a Go package, so `deps.txt` does not list it and an import-boundary rule in its own lint configuration is that file's counterpart. `npm ci` installs it, `npm run lint` is the lint wall the code rules stand on here, `npm test` runs its own suite, and `npm run build` writes into `../clientdist/browser`, which the binary embeds — so the client is built before the binary that serves it. Each screen's directory holds a `README.md` naming what the screen owns and the `end-goal/` file it implements, which is the client's `doc.go` and which `cmd/tracecheck` reads as one. |
| [`healthmonitor`](healthmonitor) | The health monitor and everything downstream of it: the window opened at a production deploy, the comparison read per target and per operation against its control (or the release below without one) and the two readings beside it — the service's own recent history and an explicit threshold — the window closed at one of four exits, the failed exit's rollback in the order the design states it, a rollback's target and the releases it undoes, the fleet kept for a rollback torn down when the last window that could return to it closes, the incident a crossing writes and its deduplication, the page an open incident with no open window fires, the error budget an objective leaves with the hold and the intent it raises, one step of the search that recovers attribution after a batch fails, and the intent a crossing raises through intake, inside the window or after it has closed. What it does to a deploy target and the control on it is behind an interface, and so is the quantity it reads. |

Each package's `doc.go` says what it owns, who may write what, which file holds what, and the path of the Markdown file that defines what it implements — an `end-goal/` file for anything the design names — and after each path whose file holds claims the package implements, in parentheses, the ids of those claims. Read that before the code. What a package leaves to a component not yet built is stated in that package's own `doc.go`, in its own words, and nowhere else: this file names no gap, and the count of them is a search over every `doc.go` rather than a list kept here to fall out of date.

## The allowed edges

[`deps.txt`](deps.txt) is the allowed package graph: one line per package naming what it may import, a `test` line for an edge that appears only in a package's tests, and the reason for every edge that needs one in the comment above the list. An arrow reads as "imports". `cmd/depscheck` is what makes the file binding — a package the file does not list is an error, an edge it does not allow is an error, and a line naming a package that does not exist is an error. The compiler already refuses a cycle; this refuses an edge that would compile. The list is not copied here, so that it exists once.

## Running it

The toolchain is pinned by [`../mise.toml`](../mise.toml). The dev database is [`docker-compose.yml`](docker-compose.yml), on port 5433 so a PostgreSQL installed on the machine keeps 5432.

```sh
docker compose up -d           # the database
go vet ./...
go run ./cmd/depscheck
go run ./cmd/tracecheck
go test -count=1 ./...
```

[`../tools/consistency-commands.sh`](../tools/consistency-commands.sh) runs the design
document's own checks, from the repository root.

The client is a second toolchain, pinned in [`../mise.toml`](../mise.toml) beside Go's, and it is built before the binary that embeds it:

```sh
cd client
npm ci                         # the package tree, from the lock file
npm run lint                   # the lint wall: what the compiler does not refuse and the code rules forbid
npm test                       # the client's own suite
npm run build                  # writes ../clientdist/browser, which the binary embeds
npm run e2e                    # the four screens in a browser, against a factory this commit builds
```

`npm run e2e` runs after `npm run build`, the binary embedding whatever `clientdist/browser` holds: it needs `psql` on the path, a reachable `DATABASE_URL`, and port 8090 free. It drops and creates the schema `factory_e2e` on that database at the start and leaves it there at the end, so two runs on one `DATABASE_URL` cannot overlap — the second drops the schema the first is serving from. The key a test declares is the owner's, read from the People view, which holds the owner's row before anything is declared.

`npm run build`'s output is the build's product and never committed, the way the Go compiler's is; `clientdist/browser` holds nothing but `.gitkeep` on a fresh clone, and `serve` answers a request for a screen with "the client is not built" until the build has run. `cmd/tracecheck` reads each screen's `README.md` the way it reads a `doc.go`: a screen directory with no `README.md`, one citing no claim, or one whose reference points at nothing, fails the build.

Every start acquires the lease and then calls `postgres.Start`, which reads the store's schema history, refuses to start against a store this version cannot read, and applies the schema. What the history does not do is alter a table: `create table if not exists` leaves one that already exists as it is, and this version declares one change — the first schema — so a dev database written while that schema was being edited is not brought forward by running against it. Drop the schema and let it be applied again, which for the dev database is `drop schema public cascade; create schema public;`. [`postgres/doc.go`](postgres/doc.go) says which caller of `Start` is not built.

The database tests read `DATABASE_URL` and fall back to `postgres://factory:factory@localhost:5433/factory`. They do not skip when the database is unreachable — a silent skip is how a green run comes to mean nothing — so an unreachable database fails them. `-count=1` is what keeps that promise: `go test` caches a result against the test binary and what the test read, and a database is neither, so a re-run with the database stopped reports the cached `ok` without opening a socket. Each database test creates a PostgreSQL schema of its own, applies the DDL inside it, and drops it when it ends, so a rerun on a database a previous run left dirty starts clean.

[`../.github/workflows/factory.yml`](../.github/workflows/factory.yml) runs the same commands against a `postgres:17` service container.

A fourth command runs the same demonstration against the model API instead of a fake, and it is the only thing that tests the stretch between a role and the provider — the credential's header, the shape of a real answer, a reply the protocol refuses, an encoding named the way a model chose to name it. It is run whenever something on that stretch changes:

```sh
FACTORY_MODEL=deepseek/deepseek-v4-flash go test -tags realmodel -count=1 -v -run RealModel ./cmd/factory/
```

`FACTORY_PROVIDER` names which provider answers — `openrouter` by default, or `anthropic` — and `FACTORY_MODEL` is that provider's model id, so the two are set together or neither is: OpenRouter's ids are namespaced and Anthropic's are not. The credential is `model.openrouter` or `model.anthropic` in `secrets.local` by the provider named, which [`../.gitignore`](../.gitignore) refuses to track; [openrouter.ai/keys](https://openrouter.ai/keys) mints the first and `claude setup-token` the second. The test fails rather than skips when the file holds no key for the provider named, for the reason the database tests do not skip, and it keeps its git repository on a failure so what the model wrote can be read. The build tag is what keeps it out of `go test ./...` and out of CI, neither of which has a credential to spend — and what the tag costs is that this one file is not compiled in the default build, so `go vet -tags realmodel ./cmd/factory/` is how a change to it is checked.

The end-to-end tests are in `cmd/factory` and run under `go test` above along with everything else. To walk the path against a real model and a real process, run it directly — [`DEMO.md`](DEMO.md) is that run as a runbook, with what to set up, what to type at each prompt, what to show afterwards, and what the run deliberately does not cover, and [`DEMO-M1-M7.md`](DEMO-M1-M7.md) is the takes below M8 beside it, each driven by `run`, `watch` and `learn` rather than by the process:

```sh
go run ./cmd/factory serve [-port 8080] -secrets <file> [-provider <name>] -model <name> [-effort <name>] -service <name>=<dir> [-service <name>=<dir> …] -area <name> [-project <name>] -targets <dir> [-human <name>] [-pace 2s] [-candidate-environments 8] [-watch-every 1s] [-every-advance 5s] [-every-watch 30s] [-every-reevaluate 10s] [-every-deferred-pages 60s] [-every-drift-sweep 60s] [-every-deprecations 300s] [-every-acceptance 60s] [-every-score 300s]
go run ./cmd/factory run -secrets <file> [-provider <name>] -model <name> [-effort <name>] -service <name>=<dir> [-service <name>=<dir> …] -area <name> [-project <name>] -targets <dir> [-human <name>] [-pace 2s] [-candidate-environments 8] [-watch 1m] [-watch-every 1s] -intent <statement> [-intent <statement> …] [-answer <text>]
go run ./cmd/factory walk <deploy-id> [-human <name>]
go run ./cmd/factory watch <service> -secrets <file> -targets <dir> [-for 1m] [-every 1s] [-human <name>]
go run ./cmd/factory learn [-dry]
go run ./cmd/factory contracts -secrets <file> -targets <dir> [-breaks <item-id>]
go run ./cmd/factory policy [-service <name>] [-area <name>] [-gate <row>] [-stage <stage>] [-project <name>] [-human <name>]
go run ./cmd/factory truncate -boundary <row-id> [-human <name>]
```

`run` reads two secrets from `<file>`: the model credential of the provider `-provider` names, which the model call resolves and sends as a bearer token, and `deploy.local`, the credential `targetseam` requires on every operation and `localtarget` never reads. `-provider` is `openrouter` by default, reading `model.openrouter`, or `anthropic`, reading `model.anthropic` — and `-model` is that provider's model id, OpenRouter's being namespaced (`anthropic/claude-opus-4.8`) and Anthropic's not. A subscription token is served `claude-haiku-4-5` and refused every model above it, which is what the second provider is for and what [`DEMO.md`](DEMO.md) records the measurement of. `-effort` is the field a fleet entry has for how long the model works before it answers, named on the one entry this interface composes and sent to whichever provider answers — OpenRouter takes it as `reasoning.effort` and Anthropic as `output_config.effort`. The factory does not check that the provider offers what is asked for: an entry naming an effort nobody offers fails at the provider's own answer, which is where an exhausted account fails too. `-service` is a service as `<name>=<path>`, the path being its git repository and created when absent, and it is given once per service the install knows: an interface has consumers and the consumers are other services in the same factory, so a run that could name one service could never demonstrate a contract. `-targets` is the directory `localtarget` runs releases from, and production's environment record is created naming it. `-human` names the human this process acts as, which `serve`, `run`, `walk`, `watch`, `policy` and `truncate` resolve to the per-person key the People mapping holds — `learn` and `contracts` take none, reading as `owner`, minting a key and a mapping where the name is new — every record names a key and a person at a terminal types a name. It is also the owner the composition's own writes are made as (default `owner`), and the one key an acting call at a screen exempts from the read-only reading. `-intent` supplies an intent's statement and is given once per decomposition — two of them is two items authored, two candidate environments live at once, and both merges ordered by the queue — and at least once. An intent that changes more than one service names them before its statement, comma separated and then a colon — `-intent 'producer,consumer: what is wanted'` — which is this interface being told what decomposition yields, a stage that decides the decomposition being a later milestone's. Where decomposition yields more than one item, Decomposition fires over the set and one verdict covers the whole of it; where an item waits on another, the run takes the layers in order, so a producer ships before the consumer whose environment is composed from it. `-candidate-environments` is how many candidate environments this platform has room for at once (default 8): a candidate that meets it waits, and that wait is written into the log, being neither a record nor a parameter of an owner's. `-area` names the area the item is in, declared where it does not exist — without one the score can read neither context factor and a human decides every gate of that item. Every factor over a build is valued here: package `exposure` derives what a change reaches from the diff and the build's resolved set, the build record carries the list, and each of the four rows over a build reads it off that record — so a number under the threshold auto-passes, the held-out sample can select, and the thresholds it learns have outcomes to learn from. A service's first release is still decided by a human at every row, which is what the supplied threshold is calibrated to. `-pace` is the least time between two model calls, two seconds by default, which is what stops a stage's retry following its refusal with nothing in between; `0` sends them back to back. `-watch` is how long the run reads its own windows before leaving what is still open, open, a minute by default, and `-watch-every` is how often it reads — a window's duration is measured and never set, so a run cannot know in advance how long to wait. `-project` names the project this take installs and works in, `default` unless given, created in the same event as production's environment for it where it does not exist yet. `walk <deploy-id>` follows the links from an existing deploy record back to its intent, printing each stored field it crosses and then every decision the item's gates left in the log.

`serve` is the one subcommand that does not exit after a pass. It acquires the lease, holds it for the life of the process, and runs each component's pass on a ticker of its own — the path's advance, which carries the merge queue and the production deploys inside it; the watch; the gate's re-evaluation of every pending row a hold stands on, which is the first caller that call has ever had; the notifier's deferred-hours pass and its drift sweep; the pass over the deprecation list; the acceptance rounds; and the score's own pass over the outcomes. One goroutine runs them, so no two run at once; each one's error is reported and the rest go on, which is what one process is not one failure means. It serves the four screens on its one port: package `screens`' own handler over the views and the calls `cmd/factory` implements, with the client's build output embedded from `clientdist`, and `GET /healthz` beside them answering with the factory version — the one route that carries neither the factory version nor a principal, because it is what a reader outside the process reads before it has either. A tick that moved something announces the home view and the lists that pass could have moved to every open subscription, so a screen already open learns that a record changed without a reload; a tick that moved nothing announces nothing, an idle install otherwise having every open screen re-read the home view on every tick and append a read event to the chained log at each one. It stops when its lease is taken: exactly one instance runs, every write from a fenced process is refused anyway, and the process reports why and exits. It exits on SIGINT or SIGTERM, shutting the server down and releasing the lease. `-every-<name>` sets any pass's interval.

A screen writes nothing a pass does not already write, with two exceptions and one field. The exceptions are a page a human fires on their own judgment, which package `notifier` already defines and no component fires, and the seam 5 field turning on, which package `policy` has always been able to write and nothing has ever called — leaving the hold a document-kind constraint requiring it puts on an item with no way to clear. The field is when the actor opened the row in Work, which `decisionlog` has carried on every close event since the log's shapes were written and which no other caller can answer for — so the interval Factory reports as how long a row was open in front of a human is readable, beside the wait and never in place of it. Two refusals are every call's, before any screen-specific check: a People row holding no duty, no obligation and lending no credential reads all four screens and acts nowhere, and a verdict is written only against the open event the row was rendered from, which is re-read at the submit.

`run` asks for no verdict. Where a firing puts a human at the row the pass writes nothing, the row stays pending in Work, and the run reports the item waiting there — so an install with no screen open is not stuck but shown as stuck. What continues such an item is the next pass, and the pass is resumable: one item's candidate is read back out of the records by `path.rehydrate`, and where the pass enters it is derived from which of its subjects the rows above it have approved. A verdict a human left between two passes reaches exactly the code the factory's own auto-pass reached — a reject returns the item to the stage the row names with an attempt counted there, an approval at a deploy row performs the deploy, and a hold leaves the row closed until a holder releases it at Work. [`cmd/factory/doc.go`](cmd/factory/doc.go) says what has no record behind it and is derived instead.

`watch <service>` is the health monitor alone against an existing database, and it is the one thing that closes an analysis window: what a run gave up on is finished here, and a window nothing closes reaches the window limit and holds that service's production deploys. `learn` is the score's own pass over the outcomes, printing what moved and what moved it. `contracts` is every query contracts make: which toolchains this factory version has an extractor for, each contract with its versions, the elements of the newest and the deprecation mark on each, which version production is running and so which one a producer's own diff is against, the consumer contracts in force per service with the release range they were derived over, and the deprecation list per marked element — and, with `-breaks <item-id>`, what one candidate would break and whom, which is the claim that "what does this break" is a query rather than an estimate, read off the records. `truncate` is the decision log's retention pass, refused while a legal hold stands and refused where nobody has authored a retention value.

`policy` prints every parameter as it is in force, where its value came from, the safeguards that reached it, and what reads it at this milestone, which is where an owner sees which parameters are read by nothing yet. It is also where the third source of the list of allowed predicate kinds shows: an unauthored list is the five kinds the factory can decide, which is what an owner extends rather than replaces. `-project` is a flag of `run`, `serve` and `policy`, defaulting to `default`; the first two create the project where it does not exist, in the same event as production's environment for it, and `policy` refuses where it does not. Every project after that one is written at Factory.

None of the six that are not `run` or `serve` takes a service name and a repository. Both are the service record's own fields: a flag naming a repository could disagree with the record, and a flag naming one service would leave a two-service install's other one unknown, so each reads every service out of the store.

Every write a human makes is at a screen, and [`DEMO.md`](DEMO.md) walks them: duty 10 in both its forms, a mitigation instructed and ended, the mark that a rollback was not caused by the release and the page a human fires on their own judgment at Ops; an intent taken in, an interview answered, a verdict at every gate, an item or an intent ended, a priority written, a commit master holds accepted, a factory hold at the production deploy row approved through and a spend ceiling cleared at Work; a project, an area, every authored parameter, the safeguards, the halt, the legal hold, the fleet entries, the permanent constraints, a service retired, a project ended and the five rows that decide a record at Factory; and the duties, the obligations, the lent credentials with their ceilings and rates, and the mapping from a key to a name at People. Each reaches the same writer through the package that owns the record. Two are calls no subcommand makes: the page, which package `notifier` already defined and nothing ever fired, and approving through a factory hold, which fires the production deploy row that hold stops the pass from firing.

The four rows that decide a record rather than an item are decided at Factory: a safeguard leaves force where its withdrawal is approved, a halt ends where its withdrawal is, a legal hold lifts where its withdrawal is, and a shortening of decision-log retention is decided rather than authored. Writing the withdrawal is one call and deciding it is another, by a human other than the one who wrote it — the row is routed away from that human, and where the two are one person the row still fires and the close says so. Each is an open event, a close event, and then the record's own approval, which package `policy` refuses where the call names no close event. The fifth is the row every version of what an agent is told fires, on the version a first start entered and no human has decided.

Drift detection is a second binary, and installing it beside the factory is substrate outside the twelve duties. It reaches its own store through `DRIFTDETECTOR_DATABASE_URL`, defaulting to the dev database with a schema of its own, and it applies that schema itself — nothing in the factory does:

```sh
go run ./cmd/driftdetector pass -secrets <file>
go run ./cmd/driftdetector show
go run ./cmd/driftdetector clear <mismatch-id> -human <name>
go run ./cmd/driftdetector install -address <address>
```

`pass` runs three comparisons: what each target a service runs on reports running, against that service's current release; the log's chain against the head this store recorded last pass, extended and nothing else; and the factory's own last check records, which is what makes a stopped factory component reach a human. `show` prints every mismatch and the last check per target, which is what makes a stopped drift detector visible rather than silent — no mismatches is not health if the last check is a week old. `clear` is the human act the design keeps here and refuses in the factory: clearing a mismatch from the factory would make it a writer of the record that says it is wrong. `install` writes the one address, mail or chat, the detector delivers its own page to when the notifier's own last check is stale or every factory last check is stale at once — the two stops with no carrier inside the factory. A factory run with no drift detector store to reach says so on standard error and decides as a factory with none installed does.

Authoring a parameter reads the subject that parameter names and no other, the record a parameter is a field of being a fact of the parameter rather than a choice: a threshold is authored on an environment for one gate row, an attempt limit on the factory-wide settings record for one stage, an item-size target on an area, and the analysis window's four on a service. Placing a safeguard takes no direction, because the direction differs per parameter and points the same way in each — an owner chooses the subject and the bound; a safeguard on `risk_threshold` is drawn on a service, keyed by the gate row it is named with, package `policy`'s own reader keying a row-scoped safeguard that way, and only a safeguard that adds a human at a gate carries a routing. The priority is the one field that orders a queue: a greater number goes first, and it orders every queue the item waits in as an item — the gates up to and including Merge to master, and the merge queue — and no deploy.

The People declaration may be empty, which is a factory where every page and every gate row reaches the owner directly — a working factory and not a misconfigured one. The owner is not a row in it: a page widens to the owner and the design gives the owner no record, so the notifier is composed with the name `-human` gives it, and every acting call is refused on a People row holding no duty, no obligation and lending no credential, the owner's own key being the one exemption.
